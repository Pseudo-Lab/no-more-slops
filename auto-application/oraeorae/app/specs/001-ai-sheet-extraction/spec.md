# Feature Specification: 결과지 AI 판독

**Feature Branch**: `001-ai-sheet-extraction`
**Created**: 2026-10-10
**Status**: Draft
**Input**: GitHub issue #2 "결과지 AI 판독 연결 (현재 예시 값으로 대체 중)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 결과지 사진을 올리면 수치가 채워진다 (Priority: P1)

가족 구성원이 건강검진 결과지 사진(또는 PDF)을 올리면, 결과지에 적힌 항목·수치·판정이 확인 화면에
채워진다. 사용자는 값을 확인·수정한 뒤 저장한다.

**Why this priority**: 지금은 예시 값이 채워져 사용자가 모든 값을 직접 고쳐야 한다. 서비스의 핵심 약속
("AI가 수치를 읽고")이 지켜지지 않아 공개 홍보를 할 수 없다.

**Independent Test**: 실제 결과지 사진을 올려 확인 화면에 결과지와 같은 값이 채워지는지 본다.

**Acceptance Scenarios**:

1. **Given** 국가건강검진 결과지 사진, **When** "결과지 읽기"를 누르면, **Then** 결과지에 있는 항목만
   결과지 수치와 판정으로 채워진 확인 화면이 나온다.
2. **Given** 결과지에 판정이 적혀 있지 않은 항목, **When** 확인 화면이 나오면, **Then** 그 항목의 판정은
   "판정 없음"으로 표시되고, 사용자가 판정을 고르거나 그대로 "판정 없음"으로 저장할 수 있다 (2026-10-12 변경:
   결과지에 없는 판정을 고르게 하면 사용자가 판정을 지어내게 된다).
3. **Given** 확인 화면, **When** 저장하면, **Then** 기존과 같이 구성원 상세 화면으로 이동한다.

---

### User Story 2 - 읽지 못하면 이유와 다음 행동을 알려 준다 (Priority: P2)

흐리거나 결과지가 아닌 사진, 너무 큰 파일, 일시적인 장애일 때 사용자가 무엇을 해야 하는지 안내한다.

**Why this priority**: 부모님 세대 사용자는 실패 이유를 모르면 이탈한다.

**Independent Test**: 결과지가 아닌 사진을 올려 안내 문구가 나오고 다시 시도할 수 있는지 본다.

**Acceptance Scenarios**:

1. **Given** 결과지가 아닌 사진, **When** 읽기를 누르면, **Then** "결과지에서 수치를 찾지 못했어요" 안내와
   함께 다른 사진을 고를 수 있다.
2. **Given** 판독 서비스 장애, **When** 읽기를 누르면, **Then** 잠시 후 다시 시도하라는 안내가 나오고
   선택한 파일은 그대로 남는다.

### Edge Cases

- 휴대폰 원본 사진(수 MB): 전송 전에 기기에서 줄여서 보낸다.
- 큰 PDF: 전송 한도를 넘으면 사진으로 찍어 달라고 안내한다.
- 여러 장짜리 결과지: 한 번에 한 장(첫 장)만 읽는다.
- 판독 키가 설정되지 않은 환경(로컬·미리보기): 지금처럼 예시 값과 경고 배너로 동작한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 올린 결과지에서 정해진 표준 항목 목록에 해당하는 수치와 결과지에 적힌 판정만 추출해야 한다.
- **FR-002**: 시스템은 결과지에 판정이 없으면 판정을 스스로 정하지 않고 비워 두어야 한다 (헌법 III).
- **FR-003**: 결과지 원본은 판독 요청 동안 메모리에서만 다루고 저장·로그하지 않아야 한다 (헌법 I).
- **FR-004**: 국외 이전 동의를 한 사용자만 판독을 요청할 수 있어야 한다 (헌법 II).
- **FR-005**: 사용자는 추출된 모든 값을 저장 전에 확인·수정할 수 있어야 한다.
- **FR-006**: 판독 실패 시 원인별 안내(결과지 아님 / 파일이 큼 / 일시 장애)를 보여야 한다.
- **FR-007**: 판독 이벤트는 단계 이름만 분석 도구로 보내야 한다 (수치·판정 제외).

### Key Entities

- **표준 검사 항목**: 키, 이름, 단위. 해마다 같은 키로 저장돼야 추이를 그릴 수 있다.
- **추출 결과**: 항목 키, 수치, 판정(정상/경계/질환의심 또는 없음).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 선명한 국가건강검진 결과지 사진에서 결과지에 있는 표준 항목 수치가 수정 없이 맞게 채워진다.
- **SC-002**: 사진을 고르고 확인 화면이 뜨기까지 대부분 20초 안에 끝난다.
- **SC-003**: 퍼널에서 `upload_submit` → `exam_save` 전환율이 예시 값일 때보다 오른다.

## Assumptions

- 판독은 개인정보처리방침과 동의서에 이미 적힌 OpenAI(미국)로 한다. 새 수탁자는 늘리지 않는다.
- OpenAI API 키는 운영자가 Vercel 환경변수에 직접 등록한다.
- 표준 항목은 국가건강검진 1차 수치 항목(신체계측·혈압·혈액)으로 시작한다. 소변 단백처럼 수치가 아닌 항목은 제외한다.
