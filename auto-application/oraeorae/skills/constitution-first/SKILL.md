# constitution-first

판단이 갈릴 때마다 사용자에게 묻는 대신 비춰 볼 문서. 왕복 횟수를 가장 많이 줄이는 장치라서 30분을 들일 가치가 있다.

## 입력
- 문제 한 문장: "___를 위해 ___를 만든다".
- 사용자가 정한 **절대 안 할 것** (예: 원본 파일 저장 안 함, 진단 안 함, 실시간 안 함). 없으면 묻는다. 이것만은 사람 몫이다.
- 다루는 데이터의 민감도(개인정보·건강·결제)와 적용되는 법(개인정보보호법 국외 이전, 전자상거래법 등).

## 절차
1. 원칙은 **5개 이내**, 각각 한 줄 제목 + 두세 줄 설명. 순서는 데이터 → 동의 → 제품 경계 → 보안 → 배포 단위.
2. 원칙마다 "이 원칙 때문에 하지 않는 것" 한 줄을 붙인다. 추상적인 선언("사용자를 존중한다")은 뺀다.
3. `speckit-constitution` 스킬이 있으면 그것으로 문서화한다. 없으면 `.specify/memory/constitution.md`에 직접 쓴다.
4. 마지막에 "Constitution Check 쓰는 법"을 한 단락 넣는다: PR마다 I~V 중 해당 없음/해당 원칙과 근거.

## 예 (오래오래)
I 건강정보 최소화 · II 처리 전 동의(민감정보·가족 공유·국외 이전 각각) · III 기록만, 진단 안 함 · IV 경계 보안(RLS + RPC, service-role 없음) · V 가장 작은 배포 단위(이슈 1 = 브랜치 1 = spec 1 = PR 1).

## 멈추는 지점 (사람 몫)
- "절대 안 할 것" 결정, 법적 표기 방식(개인정보 담당자 등).

## 산출물
