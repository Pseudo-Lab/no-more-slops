04 / IMPLEMENTATION

실제 쓰는 도구와 실행 경계

로컬 서버에서 영상을 넣으면 FFmpeg 렌더링과 기술 검사를 시작합니다. 밈 조사와 게시 판단은 별도 검토가 필요합니다.

현재 파이프라인

Codex
조사·편집 절차 설계, 스크립트 및 문구 작성 보조. 사용 모델의 정확한 이름은 실행 기록으로 확인해야 합니다.
Python
score_reel_memes.py로 선별표와 기획안을 만들고, render_instagram_reel.py로 편집 단계를 연결합니다.
ffprobe
원본의 길이, 방향, 영상·음성 스트림을 검사합니다.
FFmpeg
9:16·1080×1920·30 fps, H.264/AAC 출력, 자막·BGM·효과음·가벼운 색 보정과 기술 QA를 수행합니다.
소리·자막
원본 해시와 일치하는 검수 편집안이 있으면 장면 SRT·맞춤 BGM·효과음을 재사용합니다. 새 영상은 SRT 파일 또는 원본 시각 기준 장면 문구를 받아 시간 지정 자막으로 만들고, 없을 때만 중립 초안을 사용합니다.

로컬에서 실행

후보·원본 조회수·안전 검토를 JSON에 기록한 뒤 점수 스크립트를 실행합니다. 생성된 trend-plan.json을 이 화면의 “내 기획안 열기”로 확인할 수 있습니다.

python scripts/score_reel_memes.py INPUT.json \
  --brief trend-brief.md --plan trend-plan.json

프로젝트 루트에서 로컬 서버를 실행한 뒤 이 주소를 열고 영상을 상자에 넣습니다. 원본과 결과는 work/reel-ui-jobs/에 저장됩니다.

python -m scripts.serve_instagram_reel_ui
http://127.0.0.1:8765/

장면별 자막과 별도 BGM을 준비한 편집자는 기존 렌더 스크립트를 직접 실행할 수도 있습니다.

python scripts/render_instagram_reel.py \
  work/source.mp4 work/scenes.srt work/owned-bgm.wav \
  --output out/reel.mp4
화면에서 컷·음악·효과음·보정을 고르면 실제 FFmpeg 결과에 반영됩니다. 기본 자막은 중립 문구 초안입니다. 영상 속 실제 동작을 AI가 판별하지 않으므로 게시 전에 문구·초상 공개·화면·소리를 직접 확인해야 합니다. API 아이템은 현재 미연결이며 호출하지 않습니다.

3D 상자는 Three.js를 CDN에서 읽습니다. 네트워크나 WebGL을 사용할 수 없으면 2D 상자가 표시되며, 영상 처리는 계속할 수 있습니다.

05 / QUICK GLOSSARY

발표에 나오는 용어

선별과 렌더링에서 각각 무엇에 쓰였는지 한 줄씩 정리했습니다.

SRT
SubRip Subtitle. 시간 구간과 문장을 적은 장면 자막 원본 파일입니다.
ASS
Advanced SubStation Alpha. 렌더링할 때 글꼴·위치·모양을 적용하는 자막 형식입니다.
STT
Speech-to-Text. 음성을 글로 옮기는 기술입니다. 이 장면 자막에는 Whisper STT를 쓰지 않았습니다.
BGM / SFX
Background Music / Sound Effects. 배경음악과 짧은 효과음이며, 소리 사용 권리와 삽입 시점을 확인합니다.
FFmpeg / ffprobe
영상 인코딩·소리 합성 도구 / 원본 스트림·길이·방향 확인 도구입니다.
QA
Quality Assurance. 기술 검사와 사람의 화면·소리 검수를 합친 최종 품질 확인입니다.
API
Application Programming Interface. 플랫폼 자료를 자동으로 읽는 연결 방식이며 실시간 수집은 아직 연결하지 않았습니다.
H.264 / AAC
최종 MP4에 쓰는 영상 / 음성 압축 형식입니다. 릴스 출력의 호환성 검사를 받습니다.
