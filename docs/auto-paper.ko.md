# Auto-Paper: 근거를 따라 작성하고 검증하기

이 스킬은 반복적인 논문 심사 대응에서 재사용할 수 있는 작업 절차를 정리합니다.
방법 전체의 개선을 특정 구성 요소의 효과로 오인하는 문제, 튜닝 조건이 다른
비교, 작은 수치 차이의 과해석, 압축된 승패 표현과 제출 파일 불일치를 다룹니다.
스킬 패키지는 특정 논문의 원고·실험 데이터 없이 독립적으로 사용할 수 있습니다.

## 논문 결과물

이 작업에서 정리한 최종 4쪽 논문 [paper.pdf](../artifacts/auto-paper/shared-regularization/paper.pdf)를 함께 제공합니다.
논문 제목은 **How Shared Regularization Changes Calibration: A Case Study with Splines**입니다.

## 사용하기

저장소의 [스킬](../skills/evidence-driven-paper/SKILL.md)을 직접 읽도록 요청하거나,
skills/evidence-driven-paper 폴더를 사용하는 에이전트의 스킬 디렉터리에 복사합니다.
스킬 폴더 전체를 복사해야 참조 문서와 검사기도 함께 설치됩니다.

예시 요청:

> $evidence-driven-paper를 사용해 현재 원고와 리뷰를 확인해줘.
> 본문 4쪽 제한을 유지하고, 기존 결과로 해결할 수정과 새 실험이 필요한 지적을
> 구분해줘. 근거가 없는 주장은 좁히고, 최종 PDF와 제출 파일을 검증해줘.

> $evidence-driven-paper로 결과 JSONL에서 논문의 승패 수와 비교 분모를 확인하고,
> 본문과 보충자료가 일치하는지 점검해줘. 실험을 다시 돌릴 필요가 없는 문장 수정은
> 기존 데이터를 유지해줘.

4쪽 제한, Lean, 합성 실험, 하나의 합본 PDF는 사용자가 요구한 프로젝트에서만
적용합니다. 스킬이 자동으로 학회 채택을 보장하거나 실험 결과를 생성하지 않습니다.

## 실행 가능한 검사기

Python 3.10 이상에서 저장소 루트를 기준으로 실행합니다.

~~~sh
python3 skills/evidence-driven-paper/scripts/paper_checks.py \
  skills/evidence-driven-paper/assets/example/checks.json
python3 -m unittest discover -s tests -v
~~~

PDF 쪽수 검사에는 pypdf가 추가로 필요합니다. 개발·CI와 같은 의존성은 다음으로
설치할 수 있습니다.

~~~sh
python3 -m pip install -r requirements-dev.txt
~~~

설정 파일을 논문 프로젝트 루트로 복사하고 결과 경로, 짝짓기 키, 지표 방향,
기대 비교 개수, 제출 파일을 지정합니다.
[전체 설정과 출력 규약](../skills/evidence-driven-paper/references/harness.md)에
실행 예시와 실패 조건이 있습니다. 포함된 데이터는 사용법을 위한 가상 예제입니다.

검사기는 다음을 확인합니다.

- 행 순서 대신 명시한 키로 비교하고, 중복·누락·비정상 수치를 검출합니다.
- 승자와 비교 대상을 명시한 문장, 승패·동률 수, 비교 분모, 평균 차이를 출력합니다.
- 서로 다른 결과 집합은 기본적인 추측 없이 설정에 따라 거부하거나 누락 키를 공개합니다.
- 이전에 저장한 해시와 파일을 비교하고, 선언한 제출 파일의 존재와 PDF 쪽수를 확인합니다.

신뢰구간, 인과적 해석, 실용적 중요성, 본문의 진실성은 자동 판정하지 않습니다.
PDF 링크, 그림의 가독성, 압축파일 내부와 실제 제출본의 일치도 별도로 확인해야 합니다.
읽기 쉬운 표와 그림을 만들고 핵심 주장을 본문 안에서 완결하는 절차는 스킬이 안내합니다.

## 변경 검증과 기여 범위

테스트는 짝지어진 승패와 지표 방향, 허용하지 않은 결과 누락, 입력 변조,
잘못된 설정, PDF 쪽수 초과, 검사 보고서의 원자료 덮어쓰기 방지 등을 다룹니다.
GitHub Actions에서 Python 3.10과 3.12로 실행합니다.

새 실패 사례를 추가할 때는 실제로 달라져야 할 행동을 테스트하세요.
이번 사례의 클래스 수, 정규화 계수, 정리 개수 등을 일반 규칙으로 고정하지 마세요.
작은 문장 수정을 위해 모든 실험을 다시 실행하는 절차도 필요하지 않습니다.
