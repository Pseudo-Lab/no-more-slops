이 스킬은 `tracks/auto-post/projects/phantom-report` 전용입니다. 이 프로젝트 폴더를 작업 기준 경로로 사용하며, 아래 `scripts/`, `issues/`, `design/`, `.claude/agents/`, `outputs/`는 모두 그 기준의 상대 경로입니다. `week-NN`은 해당 활동 주차(예: `week-01`)로 바꿉니다. 스킬의 유일한 원본은 이 트랙 경로에 두고 설치본에서 별도 수정하지 않습니다.

# phantom-weekly — 주간 호 오케스트레이터

**실행 모드: 서브에이전트 파이프라인.** 단계가 순서대로 이어지고 사이에 사용자 확인이 두 번 있어 팀 실시간 통신이 필요 없다. 단계 간 데이터는 `issues/F.md` 한 파일로 넘긴다. 이 파일이 작업 기록이자 감사 추적이다.

에이전트는 `.claude/agents/`의 `scout`, `fact-checker`, `writer`. Agent 도구로 부를 때 `subagent_type`에 그 이름을, `model: "opus"`를 준다. 프롬프트에는 주차 W, 수집 기간, 할 일(모드), 읽고 쓸 파일 경로만 넣는다. 역할 설명은 에이전트 파일에 있다.

## 0. 컨텍스트 확인
1. 호 번호 F를 정한다. 호 번호는 채널 첫 발행일 기준이다: FILE 01 = 2026-10-10(토), FILE N 발행일 = 2026-10-10 + 7×(N−1)일. 사용자가 말하지 않으면 다음 발행 토요일의 번호를 쓴다. 파일 이름은 `file-NN`(두 자리), 슬라이드 표기는 `FILE NN`. 수집 기간은 발행일 직전 토요일~금요일이다. 이 하네스의 경로에 나오는 `F`는 파일 이름(`file-02` 등)이다.
2. `issues/F.md`가 있으면 어떤 섹션까지 차 있는지 보고 그다음 단계부터 이어 간다.

| 있는 섹션 | 다음 단계 |
|---|---|
| 없음 | 1 수집 |
| `## 후보`만 | ⏸ 채택 |
| `## 채택` | 2 검증 |
| `## 1차 출처` | 3 원고 |
| `## 원고` | ⏸ 원고 승인 → 4 제작 |
| `## 발행본` | 5 대조 |
| `## 최종 대조`에 "불일치 없음" | 완료. 다음 호로 |

3. 사용자가 부분 재실행을 요청하면("#003만 다시 확인", "4번 장 원고만") 해당 에이전트만 그 범위로 부른다.

## 1. 수집 — scout
- 파일이 없으면 `# FILE NN (수집 M/D~M/D, 발행 M/D 토)` 머리로 `issues/F.md`를 만든다.
- scout 결과를 받으면 후보 목록을 사용자에게 짧게 보여 준다.

## ⏸ 채택 — 사용자
- 사용자가 채택 사건과 표지 사건을 고른다. 고른 것을 `## 채택`(CASE 번호는 `cases.csv`에 이어서), 남은 것을 `## 보류`로 옮긴다.

## 2. 검증 — fact-checker (검증 모드)
- `## 1차 출처`를 쓰고 `## 채택`의 틀린 제목·요약도 고친다.
- `주의: 채택 재검토 권장`이 나오면 사용자에게 알리고 다시 고를지 묻는다.

## 3. 원고 — writer
- `## 원고`, `issues/F.prompts.json`, `## 캡션`을 쓴다.

## ⏸ 원고 승인 — 사용자
- 원고를 보여 주고 승인을 받는다. 이미지 생성은 Codex 사용량이 드니 승인 전에는 돌리지 않는다.
- 수정 요청은 writer에게 해당 부분만 넘긴다. 사실 문제면 fact-checker로 간다.

## 4. 제작 — phantom-images 스킬
- 슬라이드 HTML은 직전 발행본(`## 발행본`에 적힌 파일)을 복사해 `design/F.html`로 만들고 원고를 옮긴다.
- 나머지(이미지 생성, 렌더링, 육안 확인)는 phantom-images 절차를 따른다.
- 확정되면 `## 발행본`에 HTML·PNG·캡션 경로를 적고, 캡션을 `outputs/week-NN/F/caption.txt`로 옮긴다. 채택 사건을 `cases.csv`에 추가한다.

## 5. 대조 — fact-checker (대조 모드)
- 불일치 목록을 사용자에게 보여 준다. 고칠 것이 있으면 원고 → HTML → 렌더링을 해당 장만 다시 한다.
- 대조에서 "불일치 없음"이 나와야 발행 준비 완료다. 결과는 `## 최종 대조 (MM/DD)`에 남긴다. 그래야 다음 세션이 이 호가 끝났는지 안다.

## 에러 핸들링
- 에이전트 실패: 1회 재시도. 또 실패하면 그 단계 없이 멈추고 사용자에게 무엇이 빠졌는지 알린다. 검증과 대조는 건너뛰지 않는다. 이 둘이 이 하네스의 존재 이유다.
- Codex 401·토큰 오류: phantom-images에 적힌 재로그인 명령을 사용자에게 부탁한다.
- 출처 충돌: 지우지 않고 병기한다(fact-checker 원칙).

## 테스트 시나리오
- **정상**: "다음 호 만들자" / "FILE 02 만들자" → 파일 생성, scout → 후보 제시 → 사용자 채택 → fact-checker → writer → 원고 승인 → 제작 → 대조 "불일치 없음".
- **부분 재실행**: file-01에서 "#005만 다시 확인" → 컨텍스트 확인에서 `## 1차 출처` 존재 → fact-checker를 #005 범위로만 호출, 다른 사건 블록은 그대로.
- **에러**: fact-checker가 #002 1차 출처를 못 찾음 → "못 찾음" + 가장 이른 보도 기록 → 대조 단계에서 `SRC:`가 그 출처를 1차처럼 적었는지 짚는다.
