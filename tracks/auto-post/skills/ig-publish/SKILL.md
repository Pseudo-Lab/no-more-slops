# 인스타그램 게시

완성된 결과물을 계정에 올린다. 게시는 사람이 승인한 것만 한다. 사람이 "확인 없이 올려도 된다"고 미리 정했다면 그 범위 안에서만 올린다.

## 언제 쓰나

| 상황 | 쓸 스킬 |
|---|---|
| 아이디어·콘티 | `ad-planning` |
| 렌더·조립·QC | `product-cgi-render` |
| 계정에 올리기, 캡션, 연결 채널, 게시 후 확인 | **이 스킬** |

## 입력

작업 전에 아래 값을 정한다. 계정마다 다르니 계정 설정 파일(예: `brand/` 안 문서)에서 읽거나 사람에게 묻는다. 예시는 [references/example-account.md](references/example-account.md)에 있다.

| 입력 | 내용 |
|---|---|
| 계정 | 올릴 인스타그램 계정 |
| 연결 채널 | 동시 게시할 채널(Threads 등)과 채널별 캡션 규칙 |
| 캡션 형식 | 줄 순서, 톤, 해시태그 수와 순서, 쓰지 않는 표현 |
| 표기 규칙 | 광고 표시(제휴 링크가 있을 때), AI 표시 방식, 사람이 정한 예외 |
| 게시 세트 | 제품 하나에 올릴 게시물 종류와 순서 |
| 기록 위치 | 게시 기록을 남길 파일, URL을 알릴 대상 |

## 게시 세트 (기본형)

| 순서 | 게시물 | 만드는 법 |
|---|---|---|
| 1 | 준비 컷 캐러셀 (선택) | 제작 중 나온 장면 4~5장. 제품이 드러나는 장을 마지막에 |
| 2 | 제작 노트 캐러셀 | 표지(제품 + 제목) → 콘티 전체 → 콘티와 렌더 비교 2장 → 장면 컷 → 제품 히어로. 최대 10장. 글자는 표지와 콘티 장에만 |
| 3 | 릴스 | 최종 QC 통과본만. 시험 조립본은 올리지 않는다 |

- 모든 장은 정지 한 장으로 무엇인지 읽혀야 한다. 읽히지 않는 장은 뺀다
- 사람이 뺀 이미지는 다시 넣지 않는다

## 캡션 틀

입력의 캡션 형식이 우선한다. 정해진 것이 없으면 공식 뷰티 브랜드 계정의 짧은 형식을 기본으로 한다.

```
<짧은 제목>
<감각 한 줄 (+ 이모지)>

<공식 효능 문구 한 줄>
<제품 전체 이름(호수)>

<해시태그: 브랜드명부터>
```

- 효능 문구는 제품 분석 문서의 공식 문구 범위 안에서만 쓴다
- 근거 없는 효능, 소품을 성분처럼 부르는 말, 뜻이 흐린 문장("다음 이야기" 같은 것)은 쓰지 않는다
- 해시태그 개수 제한을 지킨다(2025-12부터 게시물당 5개)
- 제휴 링크가 있으면 첫 줄에 광고 표시를 넣고 "받을 수 있습니다" 같은 조건부 표현을 쓰지 않는다. 링크가 없으면 넣지 않는다

## 웹 업로드 절차 (instagram.com)

1. **재인코딩:** 브라우저 업로드는 한 번에 약 10MB까지다. 영상은 2-pass로 맞춘다
   ```
   ffmpeg -i final.mp4 -c:v libx264 -preset slow -b:v 3700k -pass 1 -an -f mp4 /dev/null
   ffmpeg -i final.mp4 -c:v libx264 -preset slow -b:v 3700k -pass 2 -pix_fmt yuv420p -profile:v high -movflags +faststart -c:a aac -b:a 128k up.mp4
   ```
   이미지 여러 장은 합계가 10MB 아래가 되게 JPEG(품질 92)로 바꾼다
2. 만들기 → 게시물 → 파일 입력에 올린다
3. 자르기 화면에서 **원본** 비율을 고른다. 3:4 사진과 9:16 릴스가 잘리지 않는다
4. 릴스는 편집 화면에서 커버를 따로 올린다. 3:4 격자로 잘려도 제품이 남는지 미리 확인한다
5. 캡션을 입력한다(아래 함정 참고). AI 생성물이면 **AI 레이블 추가**를 켜고 공유한다
6. **"공유되었습니다"가 뜰 때까지 다른 페이지로 가지 않는다.** 도중에 이동하면 업로드가 끊긴다
7. 게시물 URL을 새로 불러와 캡션과 AI 표시가 보이는지 확인한 뒤에 보고한다

웹에서 안 되는 것: 인스타그램 라이브러리 음원, 연결 채널 공유 토글, 이미 올린 게시물에 AI 레이블 추가, 스토리와 하이라이트. 이것들은 사람이 앱에서 한다.

## 캡션 입력 함정

- 입력창은 Lexical 편집기다. `execCommand`나 DOM 조작으로 넣은 글자는 화면에만 보이고 저장되지 않는다. 그래서 캡션이 빈 채로 게시된 적이 있다. **실제 키 입력으로만** 넣는다
- 한글 IME가 음절을 바꿀 수 있다(예: 끈 → 끌). 잘 틀리는 음절은 따로 입력한다
- 마지막 해시태그 뒤에 자동완성이 붙을 수 있다. 태그 뒤에 공백을 하나 둔다
- 게시 전에 글자 수 표시(N/2200)가 캡션 길이와 맞는지 본다
- 만들기 창에서 Escape를 누르지 않는다. 게시물 삭제 확인창이 뜬다
- 캡션 수정 순서: ⋯ → 수정 → 전체 선택 후 지우고 다시 입력 → 완료 → 새로고침해 확인

## 연결 채널 (Threads 예)

- 채널 프로필은 사람이 만든다(계정 생성). 만든 뒤에는 입력에서 정한 범위의 게시물을 함께 올린다
- threads.com → 새로운 스레드 → 파일 입력(이미지 최대 10장 또는 영상) → 캡션 → 게시. 해시태그는 Threads 규칙(주제 태그 하나)에 맞춰 빼거나 줄인다
- 올린 뒤 프로필에서 글이 보이는지 확인한다

## 기록과 전달

- 기록 위치에 날짜, 게시물, URL, 비고(업로드판, 커버, 레이블)를 남긴다
- 게시 URL을 알릴 대상에게 보낸다. 사람이 정한 범위만 보낸다(계획만 또는 결과까지)

## 게시 전 점검

- [ ] QC를 통과한 최종본인가 (시험본이 아닌가)
- [ ] 모든 장과 컷이 정지 한 장으로 읽히는가
- [ ] 캡션이 입력의 형식을 따르는가, 근거 없는 효능이나 흐린 문장이 없는가
- [ ] 글자 수 표시가 맞는가
- [ ] 원본 비율, 커버, AI 레이블
- [ ] 공유 완료 화면을 기다렸는가
- [ ] 실제 게시물에서 캡션을 확인했는가
- [ ] 연결 채널에도 올렸는가
- [ ] 기록과 전달을 했는가
