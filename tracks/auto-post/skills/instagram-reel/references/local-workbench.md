# 로컬 릴스 작업실 연동

Family Reels 제작 앱의 스킬을 재사용하는 경우에만 읽습니다. 아래 파일명과 경로는 별도로 준비한 제작 앱 루트 기준이며, 이 저장소에 앱 구현·런처·인증 설정을 함께 배포하지 않습니다. 일반 편집에서는 설치된 도구로 `SKILL.md`의 절차를 수행합니다. [공유판 출처와 범위](../../../projects/family-reels/README.md)를 참고합니다.

## 입력·렌더·검수

- `scripts/render_instagram_reel.py`는 복사본, 원본 시간축 SRT, BGM과 선택적인 효과음을 받습니다. 결과의 `instagram-reel.edit.json`을 실제 구간·문구·효과음·미리보기와 대조합니다. 검수 자산은 `scripts/reel_edit_plan.py`로 등록하며 원본·SRT·BGM·효과음 해시가 당시 기록과 일치할 때만 재사용합니다.
- `scripts/score_reel_memes.py INPUT.json --brief trend-brief.md --plan trend-plan.json`은 선택적 조회수 비교 도구입니다. JSON의 `markets`, 근거별 `platform`·`market`·`market_signal_type`·`market_context`와 사람의 안전·장면 검토를 사용합니다. 공개 웹의 발견 조사와 별개이며 전체 플랫폼 순위나 안전성을 자동 검증하지 않습니다.
- 입력과 배포 manifest에 결속된 자막·커버가 바뀌면 변경 내용을 검수하고 manifest를 다시 만듭니다. 무결성 오류를 없애려고 해시를 지우거나 검수 자산을 덮어쓰지 않습니다. 불량 SRT는 큐 번호·시간·문구를 수정하고 다시 선택합니다. 영상 전송 중단 후에는 만료되지 않은 같은 자막 토큰을 재사용할 수 있지만 수락된 토큰은 재사용하지 않습니다.

## 작가회의와 선택형 API

- 작가 역할은 온유(`writer_story`, 아트·스토리), 루카(`writer_comedy`, 트렌드·코미디), 세린(`writer_continuity`, 비주얼·모션)입니다. 같은 Codex 모델의 역할이며 실제 동료 비평·수정·응답을 남깁니다. 취향·투표·제품의 동률 정리는 객관적 품질 인증이나 사용자 승인이 아닙니다.
- `edit_boundary` 사진은 실제 편집 끝을 같은 렌더 필터로 준비한 기준입니다. 작가에게 실제 원본 이미지, 선택한 기준 사진과 해당 작업의 반려 후보·해시·실패 항목·수정 지시를 연결합니다. 제공하지 않은 참조 자산을 있다고 가정하지 않습니다.
- 2026-10-26에 확인한 작업 사본의 MiniMax 사진 경로는 별도 승인한 기준 사진 1장의 6초 생성 컷을 원본 뒤에 붙이는 방식입니다. 작가 역할은 그 경로의 단일 컷·고정 카메라 범위에서 제안합니다. 이는 공급자의 전체 기능이나 현재 사용 가능성을 보증하지 않습니다. 같은 인물의 연속 변환·중간 삽입 지원을 가정하지 않고, 실제 실행 시 모델·정책·권한·가격·길이를 다시 확인합니다.
- 새 사진 전체 영상 경로는 이야기·계획 버전 4, `ai_full`, `placement=full_video`입니다. 기본 MiniMax H3·15초·2K·9:16이며 선택한 사진을 `reference_image`로 보내고, 채택한 후보가 전체 본편이 됩니다. 사진 출처와 생성 영상의 출처를 구분하고 생성 본편에 정지사진 QA 예외를 적용하지 않습니다. 기존 버전의 계획·요청·사람 결정 기록은 유지합니다. 공식 지원 범위는 [H3 API](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)와 [참조 생성 가이드](https://platform.minimax.io/docs/guides/video-generation)에서 다시 확인합니다. 이 경로가 실제 얼굴 일치·게시 성공을 보증하지는 않습니다.
- 해당 사본의 MiniMax 한국어 내레이션은 화면 문구 입력란(최대 80자)만 TTS에 전송하고 영상·프레임·원음을 보내지 않습니다. 선택 구간보다 긴 음성은 문구나 구간을 조정합니다. 발음과 음량 균형을 듣고 검수합니다. 모델의 현재 지원 여부를 확인하고 종료된 음악 모델을 선택지로 안내하지 않습니다.
- 실행 중인 `/api/health`와 `scripts/serve_instagram_reel_ui.py`로 이번 환경을 확인합니다. `available`은 준비 상태이며 계정 권한·잔액·호출 성공의 보증이 아닙니다. API 키가 없어도 로컬 편집을 허용하며 선택한 API 실패를 로컬 처리 성공으로 덮지 않습니다. 보고서의 `external_api_calls`와 `reused_assets`를 구분하고 캐시가 재시작·용량 제한으로 사라질 수 있음을 반영합니다.
- 프롬프트는 실제 입력 범위와 현재 지원 길이 안에서 시작 → 한 변화 → 끝 상태를 표현합니다. 입력·계획·실제 전송 프롬프트의 해시를 결속합니다. 검사나 `story_evaluation.ready`는 제출 근거·검토 기록·기능 범위의 상태이며 의미·유머·지표 진위의 자동 검증이나 결제 승인이 아닙니다. 미지원 입력과 길이 초과는 프롬프트 형용사나 임의 축약 대신 계획을 수정합니다.

## 화면과 복구

- 기본 화면은 `dashboard/instagram-automation-pipeline.html`과 `dashboard/assets/`의 보물상자입니다. UI 수정은 이 진입점·애니메이션·장면 입력 흐름에 통합하며 `/editor`의 별도 화면과 구분합니다. 파일 선택·드롭은 입력 준비이고 제작 버튼이 전송을 시작합니다. 완료 후 설정 변경은 다시 만들기로 적용합니다.
- 상태 조회가 끊기면 같은 작업 ID로 재연결합니다. 조회 오류를 새 렌더나 새 유료 호출로 대체하지 않습니다. 실제 실패는 단계·원인·다음 행동, QA 불합격은 해당 검사표를 제시합니다. 이전 성공을 새 실패의 증거로 쓰지 않습니다.
- 새로고침은 저장된 ID를 조회할 수 있지만 원본 파일 객체를 복구하지 않습니다. 새 렌더에는 원본을 다시 선택합니다. 서버 재시작 뒤 작업 복구를 보장하지 않습니다. Windows 런처를 쓸 때는 현재 사용자의 `open-reel-studio.cmd`로 `reel-studio://open`을 등록하며 브라우저 확인·보안 설정을 우회하지 않습니다.
- `/engineering`의 그래프와 스킬 편집은 기록된 해시, 코드에서 추론한 관계와 미실행 상태를 구분합니다. 새 작업 접수 때 `skills-snapshot.json`과 지침 맥락 해시를 보존하고, 저장한 변경은 다음 새 작업에만 적용합니다. 정적 JS 관찰을 Python 실행이나 영상 품질 검증으로 간주하지 않습니다.

게시용 길이·용량·코덱은 해당 앱과 실제 게시 경로의 현재 제한을 각각 검사합니다. 직접 게시 구현은 `scripts/reel_instagram_publish.py`이며 연결·검수와 별도로 최신 영상·게시 글·커버·계정을 확인한 승인이 필요합니다. 게시 결과가 불명확하면 기존 상태와 계정부터 확인하며 자동 재전송하지 않습니다. 이 문서는 앱 구현이나 게시 성공의 검증 기록을 제공하지 않습니다.
