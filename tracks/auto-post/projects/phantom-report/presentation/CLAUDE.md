# 주간 발표 덱 (No-More-Slops · Phantom Report)

매주 "이번 주 발표 만들자"라고 하면 이 문서대로 덱을 만든다.

## 무엇을 발표하나
- 레포: `Pseudo-Lab/no-more-slops`의 `tracks/auto-post/projects/phantom-report/`. 발표자는 박용욱(GitHub `yongukpark`).
- 재료는 이 순서로 본다.
  1. 그 주에 내가 올린 PR 본문 (무엇 / 왜 이렇게 / 확인한 것 / 다음)
  2. `devlog/week-NN.md`: 이번 주 핵심 3줄, 문제 → 반영, 전후 비교 이미지, 다음에 확인할 것
  3. `issues/file-NN.md`, `README.md`, `.claude/`: 사실과 숫자를 확인할 때
- 다른 사람의 PR은 넣지 않는다. 내 작업만 다룬다.
- 레포 접근: GitHub MCP의 `list_commits`와 파일 읽기는 조직 토큰 정책 때문에 403이 난다. PR은 `search_pull_requests`로 찾는다. 파일, 커밋, 이미지는 공개 API(`api.github.com/repos/.../pulls/N/files`)와 `raw.githubusercontent.com`을 curl로 받는다.

## 덱 구조
이번 주를 한 줄로 정리하는 주제부터 정한다(예: "이번 주는 전체 파이프라인 구성"). 표지 부제에 그 주제를 쓴다.

1. 표지: 부제는 "이번 주: …"
2. 목차: 항목 4~5개, 마지막은 항상 NEXT WEEK
3. 내 채널 소개: 짧게. 처음 듣는 사람도 이해할 수 있게
4. 이번 주에 올린 포스트 보여주기: 실제 결과물 이미지 + 사건 목록
5. 이번 주에 바꾼 것들: 한 장에 하나씩. 형식은 **겪은 문제 → 반영한 것**. 전후 비교 이미지가 있으면 그게 그 장의 중심이다
6. 도구: 어떤 일에 어떤 도구를 썼는지(예: 그림은 GPT Image, 하네스는 Claude Code)
7. 전체 파이프라인: 단계 흐름도. 사람이 확인하는 단계는 따로 표시
8. 다음 주: "이번 주는 X, 다음 주는 Y" 한 줄 + 일정 + 집중할 것 2~3개
9. 세 줄 정리 + ACTION 한 줄(청중에게 바라는 것)
10. Q&A

- 지난주 발표의 "다음 주"가 있으면, 이번 주 덱은 그 결과부터 시작한다.
- 숫자가 있으면 쓴다(잡은 오류 건수, 넘친 px 등). 없으면 지어내지 말고 `[__]` 자리표시로 남긴 뒤 답변에서 알린다.

## 문체
- 짧은 보고서체. 제목은 결론을 한 문장으로("이미지를 키우고, 글자는 줄였다").
- 한 장에 메시지 하나. 불릿은 2~4개, 한 줄을 넘기지 않는다.
- 꾸미는 말, 과장, "단순히 X가 아니라 Y" 같은 연출은 쓰지 않는다.
- 영어 라벨은 꼭 필요한 것만(CASE, EXHIBIT, SRC 등 템플릿 장치). 본문은 한국어.
- 장마다 발표자 노트를 말투 그대로 쓴다("~했습니다").
- 모든 내용 장의 하단에 `SRC:` 줄을 두고 근거 파일을 적는다.
