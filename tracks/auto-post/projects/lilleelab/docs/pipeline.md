# 파이프라인

사람 없이 제품만 나오는 화장품 3D 광고(인스타 릴스 1개 + 사진 10장)를 만드는 흐름이다.
제품, 스토리라인, 콘티, 게시 여부는 사람이 정하고, 에이전트는 초안과 결과물을 만든다. 게시는 사람이 한다.

```
제품(사람)
  → [기획] 제품 분석 → 특징 추출 → 트렌드·레퍼런스 → 스토리라인 3안
  →【G1 스토리라인 확정】
  → [콘티 작가] 광고 콘티(컷별 그림 시트)
  ⇄ [에이전시 PM] 콘티 검토 (라운드마다 새 context, "그대로 진행"까지 반복)
  →【G2 콘티 확정】
  → [제작] 제작 설계 → 시험 3컷 ⇄ [QC] 검수 → 본 제작 ⇄ [QC] 검수 → 릴스
  → [사진] 사진 10장
  → [카피] 게시글
  → [점검] 체크리스트 (새 context, 읽기 전용)
  →【G3 게시 승인】
  → 게시(사람) → 지표 기록(사람)
```

## 역할과 결과물

| 단계 | 역할 | 결과물 |
|---|---|---|
| 제품 분석, 특징 추출, 트렌드·레퍼런스, 스토리라인 | 기획 (`planner`) | `product.md`, `research.md`, `idea.md` |
| 광고 콘티 | 콘티 작가 (`storyboard-artist`) | `storyboard.md`, 컷별 그림 시트 |
| 콘티 검토 | 에이전시 PM (`agency-pm`, 읽기 전용) | `agency-review.md` |
| 제작 설계, 키프레임, 릴스 | 제작 (`producer`) | `production.md`, 컷 영상, `video/final.mp4` |
| 제작 검수 | QC (`qc`, 읽기 전용) | `production/proto/qc.md` |
| 사진 10장 | 사진 (`photographer`) | `photos/01~10` |
| 게시글 | 카피 (`copywriter`) | `caption.md` |
| 점검 | 점검 (`editor`, 읽기 전용) | `review.md` |

기획 4단계와 콘티 문법은 스킬 `ad-planning`, 3D 렌더·조립·측정 QC는 스킬 `product-cgi-render`에 있다.

## 사람 승인 게이트

게이트는 사람만 바꾼다.

- **G1 스토리라인 확정:** 3안 중 하나를 고른다. 승인 전에는 콘티를 만들지 않는다
- **G2 콘티 확정:** 콘티를 확정한다. 승인 전에는 이미지·영상을 생성하지 않는다
- **G3 게시 승인:** 점검 통과 뒤. 게시는 사람이 직접 한다

## 콘티 검토 루프

- 콘티 작가가 판을 내면 에이전시 PM이 **매번 새 context**에서 읽고 점수와 판정(수정 후 진행 / 그대로 진행)을 쓴다
- 다음 판은 PM의 필수 수정만 반영한다. 같은 라운드에서 새 취향 요구를 늘리지 않는다
- "그대로 진행"이 나오면 사람에게 G2를 요청한다

## 제작 루프

```
제작(한 바퀴) → 자가 점검 → QC 검수 → 통과 / 수정 / 사람에게 질문
                  ↑______________ 수정 ______________|
```

- 시험 3컷부터 만든다. 3컷이 모두 통과하면 사람에게 보여 주고 본 제작 여부를 묻는다
- 한 바퀴마다 `production/proto/log.md`에 바꾼 것, 렌더 시간, 생성 횟수를 남긴다
- QC 판정은 `production/proto/qc.md`에 라운드마다 덧붙인다. QC는 제작자의 설명보다 프레임을 믿는다
- 같은 컷이 3라운드 안에 통과하지 못하면 콘티에 적어 둔 대체 방법으로 바꾼다
- 수치 기준으로 통과시킨다: 순백(255) 픽셀 0개, 기준 컷 대비 세계 평균색 채널당 10 이하, 마지막 → 첫 프레임 루프 이음매 10 이하
- **바로 사람에게 알릴 것:** 완성도를 위해 콘티·도구·예산을 바꿔야 할 때, 유료 비용이나 생성 도구 한도 초과가 필요할 때, 사람이 직접 해야 하는 일(외부 생성 도구 실행 등)이 생겼을 때

## 공통 규칙

1. 에이전트끼리는 파일로 소통한다. 다른 역할의 파일은 고치지 않는다. 단계를 시작하고 끝낼 때 `status.yaml`을 갱신한다
2. 유료 API는 사람이 승인한 것만 쓴다. 무료 도구(코드 3D 렌더, headless Chrome, ffmpeg)를 먼저 쓴다
3. 효능·성분 문구는 공식 상품 페이지에서 확인해 `sources.md`에 출처가 있는 것만 쓴다. 의약품 오인, 근거 없는 최상급, 비교 표현은 쓰지 않는다
4. 캡션 첫 줄 광고 표시, 브랜드 공식 광고 아님, AI 생성 표기를 빠뜨리지 않는다
5. 로고, 용기 글자, 색, 모양이 실제 제품과 같아야 한다. 라벨이 보이는 화면은 3D 렌더로만 만든다
6. 이미지, 영상, 음원, 글꼴은 사용 권리를 확인한 것만 쓰고 `sources.md`에 남긴다. 레퍼런스 영상 원본은 저장하지 않는다
7. 사람 얼굴, 위치, 연락처는 넣지 않는다. 원본 미디어는 커밋하지 않는다
8. 단계마다 `cost.md`에 한 줄(토큰, 생성 건수, 비용, 소요 시간)을 남긴다
9. 게시 후 `metrics.md`에 지표를 남기고, 다음 기획은 이를 근거로 한다
