# 점선과 교차부의 의미 판정

기본 실행은 `geometry-local-route-v15-semantics`입니다. v12 객체 추출과 v14 연결 검사를 유지하고, 코드가 만든 미확정 경로에 도면 표기의 의미를 검사하는 K9와 실제 접점을 검사하는 K10을 추가합니다. v12, v13, v14도 설정으로 선택할 수 있습니다.

점선의 흰 간격과 다른 선 아래로 통과하기 위한 끊김은 연결된 선을 나타낼 수 있습니다. 모델은 원본 경로의 양 끝과 주변 선팔을 보고 `continuation`, `crossing_no_join`, `junction`, `disconnected`, `uncertain` 중 하나를 선택합니다. 코드는 선택 결과를 기존 좌표와 경로에 대응시킵니다. 모델이 좌표를 생성하지 않습니다.

점선은 정렬된 반복 획, 교차부 통과는 맞은편 팔과 교차하는 다른 축, 분기는 T/점/꺾임과 실제 선팔의 근거를 먼저 코드로 확인합니다. 교차부 통과의 선택은 같은 축의 직진만 허용하며 다른 축으로 회전하거나 두 회로를 합치는 근거로 사용할 수 없습니다. 네 방향의 선이 점 없이 만나는 모호한 교차는 분기로 자동 확정하지 않습니다. 객체, 글자, 표 안을 지나는 경로도 기하 검사에서 제외합니다.

짧은 경로는 보호 영역 밖의 주변 획까지 관찰합니다. 두 획뿐인 팔은 다른 팔에 실제 반복 점선이 있고 간격이 맞아야 가설을 제안합니다. 잉크가 경로 중심에서 어긋난 경우에는 최대 3픽셀 범위의 원본 관찰을 기록하고, 후보 좌표는 유지합니다. 실제 꺾임에서 멀리 떨어진 플랜지나 글자 획은 분기의 근거로 사용할 수 없습니다.

같은 원본을 두 색상 순서로 검사하고, 두 응답이 같은 의미를 선택하며 선택 확률의 평균이 0.60 이상이어야 합니다. 선택한 의미가 코드의 경로와 맞아야 연결 근거로 인정합니다. 이전 이진 판단과 새 범주 분포를 함께 보관하며, 설명되지 않은 끊김은 검토 상태로 유지합니다.

K10은 앞의 선분 판단이 불확실해도 관측된 실제 객체 접점을 검사합니다. 원본 주변 도면과 같은 접점의 확대 화면을 이미지 한 장으로 묶고, 관측한 바깥선 위치에 마커 하나를 표시합니다. `attached`, `passes_beside`, `other_arm`, `uncertain`을 구분하며, 다른 포트나 인접한 평행선을 같은 접점으로 취급하지 않습니다. 새 경로는 모든 필요한 선 근거와 양 끝 실제 접점이 확인되어야 확정합니다. 이전 v14에서 확정한 관계는 보존합니다.

새로 확정하는 경로의 모든 축 전환점은 이전 선분 검사에서 확정됐더라도 원본을 다시 관찰합니다. 짧은 실선 팔과 주변의 규칙적인 점선 팔을 함께 세어 네 방향 팔에 별도 접속점이 없는 교차를 확인합니다. 같은 축으로 통과하는 경로는 유지하고 다른 축으로 꺾는 경로는 검토 상태로 둡니다.

K11은 새 경로 전체를 길이가 `max(72, 12 × text_h)`인 국소 창으로 나누고 절반씩 겹쳐 원본을 검사합니다. 안내 패널에는 코드의 기존 경로 구간을 표시하고, 원본 패널은 선을 덧칠하지 않습니다. 각 구간의 `line_only`, `intervening_symbol`, `uncertain`을 구분해 객체 목록에 없는 중간 기호도 통과하지 않도록 확인합니다. 초록색으로 표시한 원래 두 끝점 객체만 예외이며, 창의 절단점은 예외가 아닙니다. 모든 구간에서 두 색상 순서가 `line_only`에 동의해야 연결을 확정합니다. 원본에서 끝점 객체에 닿은 닫힌 사각 외곽이 객체 범위 밖으로 확장되고, 경로가 그 외곽의 여러 변이나 한 긴 변을 따라가면 별도의 검토 상태로 둡니다. 몸체가 일부만 추출된 경우 그 외곽을 배선으로 쓰지 않도록 하는 검사이며, 닫힌 배관 고리와 기호 몸체의 유형을 기하만으로 확정하지 않습니다. 객체 범위와 경로 좌표를 바꾸지 않습니다. 한 페이지에서 최대 96개 경로와 384개 창을 검사하며, 빠진 응답이나 예산 초과 구간이 있으면 검토 상태로 둡니다.

페이지당 추가 검사 한도는 선 요소 192개와 접점 192개입니다. 각 요소는 두 색상 순서로 검사합니다. 우선순위는 기존 경로의 미확정 요소 수, 공유 관계 수와 실제 전체 경로 응답을 사용하며 정답 파일은 사용하지 않습니다. 한도로 검사하지 못한 경로는 `connection_review`에 남습니다.

API의 `objects`, `relations`, `connection_review` 계약과 검토 JSON/PNG는 유지합니다. `connection_review.graph.entities`의 `semantic_geometry`, `semantic_interpretation`에서 코드의 가설, 실제 범주 분포, 선택 의미와 이전 판정 상태를 확인할 수 있습니다. 새 경로의 모든 원본 구간의 응답은 `semantic_route_context`에 남습니다. 확정 연결은 `relations`에만 들어갑니다. 의미 검사 횟수와 회복된 관계는 `graph.summary`에 기록합니다. 후보 수나 미확정 경로의 가시성을 정확도로 계산하지 않습니다.
