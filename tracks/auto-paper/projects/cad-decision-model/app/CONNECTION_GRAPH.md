# 연결 경로와 검토 후보

이 문서는 선택 가능한 이전 버전 `geometry-local-route-v14-graph`를 설명합니다. 현재 기본 실행은 [v15 의미 검사](CONNECTION_SEMANTICS.md)입니다. 객체와 글자를 추출하는 v12 코드에 v13의 연결 보완과 v14의 선분, 접점 검사를 적용합니다. `CAD_ALGORITHM_REVISION`으로 v12와 v13도 선택할 수 있습니다. 접수된 작업의 실행 버전은 서버 설정을 바꿔도 유지됩니다.

코드는 원본 선망에서 객체의 접점과 가능한 경로를 찾습니다. 같은 선분을 서로 다른 연결에서 검사할 때는 물리적 좌표가 같은 판단을 공유합니다. 서로 다른 평행선, 다른 접점이나 객체의 반대편 포트에는 판단을 공유하지 않습니다. 객체 몸체를 통해 두 선망을 합치지 않습니다.

좁은 그림과 넓은 그림의 판단이 충돌하면 기존 점수를 모두 보존하고, 원본 획을 유지한 국소 그림으로 한 번 더 검사합니다. 두 색상 순서가 모두 연결을 지지하고 평균 점수가 0.60 이상이어야 새 연결을 확정합니다. 기존의 강한 거절이나 순서에 따른 충돌은 새 긍정 점수 하나로 덮어쓰지 않습니다. 두 인접 선이 같은 접점의 대안인 경우에는 코드가 만든 ‘선 A’, ‘선 B’, ‘유일한 연결을 정할 수 없음’ 선택지를 사용하고, 선택 결과를 기존 좌표에 대응시킵니다. 모델은 좌표나 선을 생성하지 않습니다.

한 객체 쌍에 다른 실제 경로가 있으면 대안도 보관합니다. 새 대안은 선분, 분기점과 두 접점이 확인되어야 채택합니다. 페이지마다 추가 국소 검사 수를 제한하며, 검사하지 못한 후보는 삭제하지 않고 검토 대상으로 남깁니다. 세 개의 막대로 표시된 플랜지와 배관 사이의 짧은 단절도 제한된 기하 조건에서 후보로 복원하며, 기하 규칙만으로 연결을 확정하지 않습니다.

기존 `relations`의 `type: "connected"`는 확정된 연결입니다. v14에서는 결과 JSON에 `connection_review`를 추가합니다.

```json
{
  "connection_review": {
    "schema": "cad_connection_review_v1",
    "candidates": [{
      "id": "c0001", "a": "s1", "b": "s2",
      "state": "review_needed", "path": [[10, 20], [30, 20]],
      "reason": ["conflicting_crop_judgments"]
    }],
    "alternative_candidates": [],
    "coverage": {"ports": [], "line_ends": []},
    "graph": {"entities": [], "candidate_routes": []},
    "summary": {"confirmed_candidates": 0, "review_needed_candidates": 1}
  }
}
```

위 JSON은 필드 설명을 위한 예시이며 실제 도면 결과가 아닙니다. 후보의 상태는 `confirmed`, `review_needed`, `rejected`입니다. `review_needed_candidates`에는 미확정 대안 경로도 포함합니다. 검토 후보와 미확정 접점은 확정 연결 수나 정답률에 포함하지 않습니다. 원래 선망에서 관측한 선 끝도 보관하며, 연결된 접점에 해당하지 않는 선 끝은 검토 대상으로 남깁니다.

API 결과와 함께 `input_review.json`과 `input_review.png`를 다운로드할 수 있습니다. 결과 화면의 ‘검토 필요’ 모드는 원본 위에 후보 경로와 미확정 접점, 선 끝을 주황색으로 표시합니다. 실제 모델 점수, 이전 판단, 추가 판단, 대안 경로와 후보가 채택되지 않은 이유는 검토 JSON에서 확인합니다.

이 방식은 자동 확정의 누락을 줄이고 남은 후보를 확인할 수 있게 합니다. 관측한 선망 밖의 모든 연결이나 모든 종류의 도면을 빠짐없이 복원한다는 보장은 아닙니다. 검증에는 기존에 검수한 일부 도면 구간을 사용하며, 새 연결 개수를 정확도 개선으로 해석하지 않습니다. 논문 기준의 공개 벤치마크 결과와 폴더의 비공개 검수 결과는 구분합니다.
