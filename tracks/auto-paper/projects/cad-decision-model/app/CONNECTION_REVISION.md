# 연결 추출 보완

이 문서는 이전 v13의 보완을 설명합니다. v14의 공유 선분 검사와 검토 결과 형식은 [연결 경로와 검토 후보](CONNECTION_GRAPH.md)에 있습니다. 현재 기본 실행은 [v15 의미 검사](CONNECTION_SEMANTICS.md)이며, v13은 명시적으로 버전을 선택해 계속 실행할 수 있습니다.

`geometry-local-route-v13-connections`는 v12의 객체 검출, 박스 조정, 분류와 글자 추출 코드를 유지하고 연결 후보와 추가 검증을 보완합니다. 기존 `vendor/v12`의 22개 소스 파일과 `freeze.json`은 변경하지 않습니다. 논문에 기록된 v12와 실행 결과의 v13을 별도 버전으로 표시합니다.

큰 선망에서는 객체마다 실제 선 경로상 가까운 이웃 두 개를 추가 연결 후보로 검사합니다. 원본에 관측된 짧은 점선과 실제 분기점 사이의 간격도 제한된 조건에서 후보로 추가합니다. 가까운 도형을 직접 연결하거나 교차선을 분기점으로 간주하지 않습니다.

모호한 점선 경로에는 한 번의 추가 원본 문맥 검사를 적용합니다. 같은 분기 그림이 완전히 포함하는 직선 검사는 중복을 제거하며, 포트 바깥 구간의 중복 검사는 실제 객체 접촉을 확인하는 K6 검사로 넘깁니다. 기존의 강한 경로 거절과 응답 누락은 추가 채택으로 바꾸지 않습니다. 흰색이나 점선 간격에 놓인 표시점은 같은 원본 선에서 관측된 픽셀로만 옮기며, 출력 경로와 객체 좌표는 유지합니다.

추가 연결은 경로와 양 끝점의 모델 증거가 있어야 합니다. 추가 문맥 판단과 큰 선망의 보충 쌍 검사에서는 두 색상 순서가 모두 연결 쪽을 지지하고 평균 확률이 기존의 0.60 기준을 만족해야 합니다. 짧은 점선 후보에도 기존의 쌍 판단, 경로 검사와 끝점 검사를 적용합니다. 실제 선망의 원본 label 집합과 기존 포트가 그대로이며 새 포트의 접촉만 복원한 경우에는 기존 net 번호를 유지합니다. 서로 다른 원본 선망이나 객체 반대편 포트를 합치지 않습니다.

`CAD_ALGORITHM_REVISION`을 `geometry-local-route-v13-connections`로 지정하면 v13을, `geometry-local-route-v12`로 지정하면 논문 기준 버전을 실행합니다. 접수된 작업에는 실행 버전을 저장하므로, 서버 설정을 바꿔도 대기 중인 작업의 버전은 유지됩니다.

```sh
CAD_ALGORITHM_REVISION=geometry-local-route-v13-connections uv run uvicorn cad_api.app:create_app --factory --host 127.0.0.1 --port 8088 --workers 1
```

`/health`, 결과 JSON의 `meta.algorithm_revision`, `meta.api.algorithm_revision`에 실제 실행 버전이 표시됩니다. v13 결과에는 `baseline_revision`과 네 보완 파일의 SHA256도 기록합니다. Decision Model의 엔드포인트와 모델은 기존 backend 설정으로 계속 분리해서 바꿀 수 있습니다.

기존 이미지 폴더 결과의 연결만 다시 검사할 때는 저장된 전체 `objects` 배열을 재사용했습니다. 부분 정답 구간에 대해 누락, 오연결, 기존 정답 연결 보존을 비교합니다. 추가 연결 개수와 검수되지 않은 쌍은 정확도 수치로 사용하지 않습니다. 폴더 평가와 공개 벤치마크 논문 평가는 별도 자료입니다.
