# 비교·종합 설계

이 서베이는 논문을 나열하지 않고 분류 → 비교 → 종합 → 연구 의제 순서로 정리한다. [정보 추출](extraction.md)의 코드로 분류하고, 이 문서의 비교 질문으로 결과를 맞댄다. 그다음 공통 패턴, 상충 결과, 기술적 공백을 찾아 연구 의제로 묶는다.

## 비교 질문

결론이 갈리는 질문을 장(RQ)마다 미리 정했다. 각 질문은 검증할 명제로 적는다. 논문의 결과가 명제를 지지하는지, 반박하는지, 조건에 따라 다른지, 효과가 없다고 보고하는지를 기록한다.

| ID | 장 | 질문 | 검증할 명제 (지지 = 명제가 맞다) |
| --- | --- | --- | --- |
| `Q-FORMAT` | RQ1 구성 | 쌍비교와 점수형 중 무엇이 사람과 더 일치하는가? | 쌍비교(상대 비교) 판정이 점수형(절대 평가)보다 사람 판정과 더 일치한다. |
| `Q-MULTI` | RQ1 구성 | 앙상블·토론이 단일 판정보다 나은가? | 여러 판정 모델의 집계·배심원·토론이 단일 판정보다 사람과 더 일치하거나 더 견고하다. |
| `Q-SCALE` | RQ2 신뢰성 | 큰 모델·추론 모델일수록 편향이 줄어드는가? | 더 크거나 더 강한(추론형 포함) 판정 모델일수록 편향이 적고 사람과 더 일치한다. |
| `Q-SELF` | RQ2 신뢰성 | 자기선호 편향은 실재하는가? | 판정 모델은 품질을 통제해도 자기 출력이나 같은 계열 모델의 출력을 더 높게 평가한다. |
| `Q-HARD` | RQ2 신뢰성 | 어려운 과제·고품질 응답에서 일치도가 떨어지는가? | 과제가 어렵거나, 전문성이 필요하거나, 비교 대상 응답의 품질이 비슷하게 높을수록 사람과의 일치가 떨어진다. |
| `Q-COT` | RQ3 개선 | CoT·설명이 판정을 개선하는가? | 판정 전에 추론·설명을 생성하게 하면 판정 정확도나 사람 일치가 높아진다. |
| `Q-REF` | RQ3 개선 | 정답 참조는 도움이 되는가? | 정답·참조 답을 주면 판정이 좋아진다. (참조에 끌려 판정이 나빠지는 앵커링은 반박으로 기록한다.) |
| `Q-FT` | RQ3 개선 | 작은 파인튜닝 판정 모델이 GPT-4급을 따라잡고 일반화되는가? | 판정 전용으로 학습한 작은·공개 모델이 GPT-4급 독점 모델 판정과 비슷하거나 낫고, 학습 분포 밖에서도 유지된다. |
| `Q-EXPERT` | RQ4 응용 | 전문 분야에서 LLM 판정이 전문가를 대신할 수 있는가? | 의료·법·과학·교육 등 전문 분야에서 LLM 판정이 전문가 판정과 전문가끼리의 일치 수준으로 맞는다. |
| `Q-ATTACK` | RQ5 보안 | 판정 모델 공격은 쉬운가? | 적은 비용의 조작(문구 삽입, 형식 변경, 프롬프트 주입 등)으로 판정 결과를 크게 바꿀 수 있다. |
| `Q-DEFENSE` | RQ5 보안 | 방어는 효과가 있는가? | 제안된 방어(탐지, 견고화 학습, 프롬프트 방어 등)가 공격 성공률을 의미 있게 낮춘다. |

## 주장 기록 형식

논문마다 위 질문에 답하는 주장만 뽑는다. 해당 질문이 없으면 빈 목록이다. 한 논문이 여러 질문에 답하면 여러 개를 쓴다.

| 필드 | 내용 |
| --- | --- |
| `question` | 위 표의 ID |
| `direction` | `support`(명제 지지), `refute`(명제 반박), `conditional`(조건에 따라 다름), `null`(차이·효과 없음) |
| `claim` | 논문이 보고한 결과 한 문장 (한국어) |
| `condition` | 결과가 성립한 조건: 과제·분야, 판정 모델, 비교 대상 등. 초록에 없으면 `null` |
| `evidence` | 초록에 나온 수치 그대로. 없으면 `null` |
| `basis` | `own_method`(논문이 제안한 방법의 효과 보고), `evaluation`(기존 방식들을 독립적으로 비교·분석). 제안 방법의 성과는 긍정 쪽으로 치우치기 쉬워 둘을 나눠 집계한다 |

결과 파일은 `data/synthesis/results/<batch>.jsonl`이고 한 줄에 논문 하나를 쓴다.

```json
{"key": "arxiv:2306.05685",
 "biases": ["position", "verbosity", "self_preference"],
 "mitigation": ["swap", "cot", "reference"],
 "claims": [{"question": "Q-SELF", "direction": "support", "claim": "GPT-4와 Claude는 자기 응답을 선호하는 경향을 보인다.", "condition": "MT-Bench 쌍비교", "evidence": null, "basis": "evaluation"}]}
```

## 코드 재분류

추출 단계에서 `biases`·`mitigation`의 `other`가 많았다(편향 599편, 개선책 330편). 표본을 읽고 반복되는 유형을 새 값으로 만들었다. 같은 배치에서 두 목록을 새 값 집합으로 다시 쓴다.

| 필드 | 묶음 | 값 |
| --- | --- | --- |
| `biases` | 제시 방식 | `position`, `verbosity`, `style`(문체·형식 선호), `anchoring`(정답·레이블·이전 점수에 끌림) |
| | 판정자–생성자 관계 | `self_preference`(자기·같은 계열 선호) |
| | 사회·권위 | `authority`, `sycophancy`, `social`(인구통계·정치·문화 편향) |
| | 일관성 | `inconsistency`, `prompt_sensitivity` |
| | 능력 한계 | `leniency`(관대·엄격 채점, 척도 쏠림), `competence`(오류 미탐지, 어려운·전문 과제 실패), `criteria`(사람과 다른 평가 기준, 차원 간 간섭) |
| | 기타 | `leakage`, `adversarial`, `other` |
| `mitigation` | 프롬프트 | `cot`, `rubric`, `reference`, `decomposition`(과제·기준 분해, 원자 단위 검증), `prompt_optimization`(판정 프롬프트 자동 탐색) |
| | 집계 | `swap`, `ensemble`, `critique_refine`(비평·재검토, 다단계 감사) |
| | 학습 | `fine_tuning`, `calibration`, `internal`(내부 표현 탐침·조향) |
| | 외부 근거 | `tool_grounding`(도구·코드 실행·검색으로 검증), `human_in_loop`(사람 개입·능동 학습), `abstention`(판정 보류·선택적 판정) |
| | 기타 | `other` |

## 이후 단계

1. 주장 추출과 코드 재분류를 한 번에 한다 (`app/synthesize.py`).
2. 질문별로 지지·반박·조건부·효과 없음을 집계하고, 조건별로 나눠 결과가 갈리는 이유를 본다.
3. 결과가 갈리는 질문의 핵심 논문은 전문으로 조건과 수치를 확인한다.
4. 공백은 세 갈래로 찾는다: 코드 교차표의 빈칸, 저자가 밝힌 공백·한계의 반복 주제, 해결되지 않은 상충 질문.
5. 장마다 분류 → 비교 표 → 공통 패턴 → 공백 순서로 쓰고, 마지막 장에서 연구 의제로 묶는다.
