# SecondChance v13 심화 해설서

이 문서는 [영문 원고](paper.json)의 문제 제기, 비교 논문, 수식, 실험 설계와 결과를 연결해서 읽기 위한 해설이다. 원고와 함께 v13으로 갱신했다. **v13의 새 작업은 논증·문헌 검토·도표·보고 구조의 개정이며 새 모델 성능 실험이 아니다.** 근거는 보존된 v11 정책 실행과 v12 상태 감사다. 자연 발생한 LLM 이력, 장기 진화 후 재발, 비교 논문의 원래 구현에 대한 우위는 아직 측정하지 않았다.

## 1. 이번 원고가 답하려는 질문

평가기를 고쳤다면 과거 점수표를 다시 계산할 수 있다. 그러나 운영 중인 프로그램이나 스킬이 함께 고쳐졌다고 볼 수는 없다. 평가기 오류 때문에 좋은 후보를 거절했다면 그 후보는 아직 보관함에 있고, 현재 채택한 프로그램은 그대로이며, 잘못된 거절을 설명하려고 쓴 교훈도 다음 선택에 영향을 줄 수 있다.

이때 필요한 의사결정은 “과거 답이 사실 정답이었는가”에서 끝나지 않는다. **지금 실제로 사용하는 상태를 무엇으로 바꾸며, 그 상태가 다른 입력에서도 작동하고, 이미 유효했던 변경을 보존하는가**를 확인해야 한다. SecondChance는 이 질문에 답할 평가 계약을 먼저 만드는 연구다.

논문의 중심 주장은 강한 새 알고리즘이 이미 이겼다는 것이 아니다. 점수 회복·후보 성공·현재 상태 회복을 구별하지 않으면 알고리즘의 성과 자체를 잘못 정의할 수 있다는 주장이다. 저자가 작성한 작은 환경에서 이 차이를 실제 실행으로 만들고, 강한 중립 비교가 제안을 이기는 경우까지 보존했다. 다음 실제 모델 실험에서 무엇을 관측해야 하는지를 명확히 하는 데 가치가 있다.

## 2. 목차를 왜 이렇게 바꾸었는가

기존 원고는 연구가 진행된 순서에 가까웠다. 새 원고는 독자가 주장을 평가하는 순서로 정리했다.

| 본문 절 | 독자가 확인해야 할 것 | 이 연구의 답 |
| --- | --- | --- |
| Introduction | 실제 문제와 기존 방법을 더 알아야 하는 이유 | 평가기 정정 뒤에도 남는 프로그램·교훈·통합 상태의 문제 |
| Related Work | 무엇이 이미 알려졌고 무엇을 더 구별하는가 | 자기 수정, 후보 선택, 영속 기억, 평가 타당성, 비용 곡선을 분리 |
| Problem Formulation | 실험 단위와 성공의 뜻 | 고정 요구사항·승인된 교정·E1/E2/E3 endpoint |
| Method | 무엇을 기록하면 그 성공을 주장할 수 있는가 | 동일 상태 fork·실제 통합·상태별 감사·면적 오차 bound |
| Experimental Setup | 어떤 자료·절차·예산으로 확인했는가 | 12 작성 이력·7절차·2예산·168 중첩 궤적 |
| Results and Analysis | 제안에 불리한 결과도 포함하는가 | neutral 동률 및 B=5 비용·부작용 우위, 양방향 측정 오차 |
| Discussion and Limitations | 어디까지 일반화할 수 있고 다음 반증은 무엇인가 | 실제 LLM·독립 교정·확률적 상태·장기 진화는 후속 과제 |
| Conclusion / Appendices | 근거 범위가 결론에서도 유지되는가 | 측정 계약의 성과만 결론에 남기고 경로·해시·실패는 부록 |

학회 이름이나 두 단 조판을 붙인다고 과학적 완성도가 생기지는 않는다. 현재는 특정 학회 규정을 동일하다고 가정하지 않는 중립 preprint다. 본문에서 문제·가정·기여·근거·반증 가능성을 연결하고, 원자료와 검토 범위를 별도 기록으로 확인할 수 있게 했다. 여전히 실제 모델 연구를 위한 핵심 관문이 남아 있다.

## 3. 그림 1: 세 endpoint를 구별하기

![그림 1: 저장 출력 재채점, 후보 새 실행, 통합 상태 새 감사의 차이](../figures/second_chance/overview.svg)

**E1은 저장 출력 재채점이다.** 어제 저장한 응답의 bytes를 바꾸지 않고 새 평가기를 적용한다. 답을 다시 생성하지 않고 현재 프로그램도 바꾸지 않는다. 과거 잘못된 평가에 대한 회계 정정이다.

**E2는 후보의 새 실행이다.** 거절했던 후보를 새 프로세스에서 개발 입력에 실행한다. 저장된 정답을 꺼내 보여 주는 것보다 강한 증거다. 그러나 개발 입력 하나를 외운 프로그램도 성공할 수 있다. 현재 채택한 프로그램에 그 후보를 통합했는지도 별도 문제다.

**E3는 실제 통합 상태의 새 감사다.** 어떤 프로그램을 통합했는지, 어떤 교훈이 활성 상태인지, 이후의 유효한 변경이 남았는지 함께 고정한 후 새로운 프로세스에서 감사한다. 논문에서 말하는 현재 회복에 가장 가까운 endpoint다. 다만 세 개의 작성 입력에서의 감사가 프로그램 전체 정확성을 증명하지는 않는다.

실제 B=8 결과에서 저장 점수는 12/12 이력에서 개선되지만 재채점만 한 현재 상태는 0/12 회복이다. 선택 정책의 개발 실행은 12/12 성공하지만 현재 초기 감사는 4/12 성공으로 줄어든다. 이 수치는 “세 endpoint를 같은 것으로 계산하면 잘못된 결론을 낸다”는 구성된 반례다. 일반 LLM에서 3분의 1만 회복한다는 발생률 추정으로 읽으면 안 된다. B=5의 neutral joint는 예산 예약 때문에 개발 실행 자체가 4/12인 별도 행이므로 그림의 12/12를 모든 예산·정책에 복사하면 안 된다.

## 4. 요구사항과 평가기 교정은 어떤 관계인가

과제 G는 두 유리수의 정확한 부호 있는 합이다. 예를 들어 정답이 음수라면 음수 결과를 내야 한다. 작성한 old evaluator는 정답의 절댓값을 비교해 부호를 지웠다. new evaluator는 같은 G의 정확한 부호를 비교한다. 요구사항을 바꾸지 않고 평가 구현의 오류를 고친 상황이다.

이 구분이 없으면 “과거에는 틀렸지만 지금 새 목적에서는 맞다”를 “과거에 부당하게 거절됐다”로 잘못 바꾼다. 새 요구사항을 반영하는 적응 연구와 과거 판정의 오류를 복구하는 연구는 대상이 다르다. 실제 자료에서는 old assertion, new assertion, 고정 요구사항, 반례, 허용되는 정답 대안과 독립 승인자를 보존해야 한다.

이 fixture의 교정 정당성은 저자가 작성한 산술 계약으로 정해진다. 실제 사람의 독립 검토나 외부 oracle이 승인한 교정 이력은 없다. 모델 비평자가 교정에 동의한다는 사실도 승인 독립성을 만들지 않는다. 애매한 요구사항이나 논쟁 중인 교정은 보류하고 전체 선정 흐름에 남겨야 한다.

응답 파서는 Python `Fraction`과 제한된 숫자 문법을 사용한다. `FINAL=-2/3`와 `FINAL=-4/6`처럼 수치가 같은 유리수는 허용한다. 0분모, 비수치, 임의 prefix, 과도한 길이는 거절하고 응답을 코드로 `eval`하지 않는다. 이는 채점 구현의 신뢰 경계이며, 실제 자연어 정답 판정까지 해결한 것은 아니다.

## 5. 상태 전체를 기록해야 하는 이유

현재 상태는 후보 프로그램 ID만으로 정해지지 않는다. 이 실험의 상태에는 계산 연산, 교훈 텍스트와 활성·보류 여부, 보존해야 하는 후기 변경이 포함된다. 후기 변경은 `FINAL=` prefix와 JSON trace 형식이다. 좋은 과거 후보를 통째로 되돌리면서 이 변경을 지우면 다른 기능을 망가뜨린 복구가 된다.

교훈은 “부호가 다른 두 항의 합이면 절댓값 풀이를 사용하라”는 작성 규칙으로 동작한다. 초기 입력은 같은 부호, 다른 panel은 반대 부호의 음수 합으로 만들었다. 프로그램을 고쳐도 잘못된 교훈이 살아 있으면 초기 성공 뒤 다른 입력에서 실패할 수 있다. 이 메커니즘은 코드에 의도적으로 들어 있으므로 LLM이 실제로 그런 교훈을 배웠다는 관측은 아니다.

`integrate`와 `lesson_suspend`가 실제 상태 변경이다. 저장 재채점과 후보 실행은 상태를 바꾸지 않는다. 공통 부모 hash, 후보 artifact hash, pre-lesson/final snapshot을 대조해 분기를 복원한다. 이 엄격함은 이후의 면적 계산에 필요한 가정이다. 실제 에이전트라면 파일, 검색 인덱스, 도구 응답, 캐시, 모델 설정과 외부 서비스 상태까지 포함해야 할 수 있다.

## 6. 어떤 비교가 공정한가

모든 정책은 같은 이력과 후보 네 개, 같은 corrected development grader, 같은 허용 정보와 같은 비용 상한을 받는다. 계보 힌트는 정합하거나 잘못된 방향을 가리키도록 작성되어 있다. neutral도 그 정보를 받지만 순서 결정에 사용하지 않는다. 정보 접근 권리를 같게 한 상태에서 힌트 사용 여부를 비교하는 것이다.

| 절차 | 선택 | 교훈 |
| --- | --- | --- |
| no repair | 아무것도 하지 않음 | 유지 |
| rescore only | 저장 출력 재채점 | 유지 |
| neutral early-stop | 고정 보관함 순서, 개발 양성 첫 후보 | 유지 |
| selection only | 계보 힌트 우선, 같은 개발 양성 기준 | 유지 |
| lesson only | 현재 프로그램 유지 | 활성 교훈 보류 |
| neutral joint | 중립 선택, 교훈 비용 예약 | 활성 교훈 보류 |
| selective joint | 힌트 우선 선택, 교훈 비용 예약 | 활성 교훈 보류 |

단순 exhaustive replay만 비교하면 비용을 많이 쓰는 약한 기준을 만든다. 실제로는 첫 성공에서 멈추는 neutral이 중요하다. 비용은 재채점 1, 후보 새 실행 2, 통합 1, 교훈 처리 1의 **작성 작업 단위**다. B=5와 B=8은 같은 상한이고, 모두가 같은 양을 쓰도록 강제하지 않는다. early stop으로 덜 쓴 것도 결과다. 모델 토큰·금액·CPU와 같다고 가정할 수 없다.

## 7. 12, 168, 292, 876, 840을 혼동하지 않기

**12는 작성 이력 템플릿 수다.** 유용한 거절 후보가 있는 8개와 없는 4개를 모두 남겼다. **168은 12 × 7정책 × 2예산의 중첩 경로 수**다. 같은 이력과 입력을 여러 정책으로 돌렸으므로 168개의 독립적인 자연 이력이 아니다.

v11의 전체 로컬 subprocess는 1,048회다. 그중 coarse checkpoint 감사는 168 × 5 = 840회이고, 별도 fixed-artifact memory 대비의 감사가 24회다. 이 864회 외에 후보 실행과 작성된 추가 입력 검사가 있다. 전체 실험의 유일한 산술 입력은 6개다.

v12의 성공 follow-up은 292개의 새 상태 subprocess다. 각 호출에서 초기·다른 입력·비영향 입력 세 panel의 응답을 내므로 출력은 876개다. 세 panel을 재사용한 예측 수가 늘었을 뿐 독립 표본이 늘지는 않았다. 궤적 간 감사 cache는 사용하지 않았다. 동일 궤적 안에서 같은 상태 bytes가 다시 나타나면 순수 결정론적 worker 가정 아래 새로 관측한 값을 재사용한다.

이 때문에 292 대 840을 일반 LLM의 비용 절감률로 발표할 수 없다. 확률적 모델이면 같은 상태에서도 응답이 달라지고 여러 샘플이 필요하다. 새로운 감사 비용은 원래 제어 정책 비용 축 밖의 별도 장부다. 사후에 감사 비용을 원래 B에 더하면 알고리즘의 실행 가능성과 지표의 의미 자체가 달라진다.

## 8. 회복과 재발 지표의 분모

초기 회복은 통합 상태의 초기 입력 감사 성공이다. 같은 상태의 다른 입력에 대한 유지 실패와 구별한다. 첫 성공이 없는 절차에서 “회복 후 실패율=0”이라고 쓰면 오해가 생긴다. 분모가 0이므로 조건부 값은 `null`이다.

전체 시작 이력 중 초기 회복이 없거나 다른 입력에서 실패한 비율은 실패 부담을 나타낸다. 초기 성공 이력 중 다른 입력에서 실패한 비율은 조건부 유지 실패다. 둘은 다른 estimand다. 유용한 거절 후보가 없는 이력을 빼면 실제 운영에서의 실패 부담을 과소평가하므로 12개 전체 분모를 유지한다.

원시 필드 `strict_recurrence`는 역사적 이름이다. 이 실험에서 `later`는 시간이 흐른 뒤 모델이 재진화했다는 뜻이 아니라 **같은 final state에 다른 입력을 준 감사**다. 따라서 장기 재발률로 부르지 않고 cross-panel 유지 실패로 설명한다. 진짜 진화 재발은 복구 이후의 새 후보·새 교훈·새 선택을 포함한 별도 경로가 필요하다.

## 9. 강한 neutral이 만든 부정 결과

| 예산 | 비교 | 초기 / 다른 입력 성공 | 평균 작업 단위 | 비영향 기능 손실 |
| --- | --- | --- | ---: | ---: |
| 5 | neutral joint | 4/12 / 4/12 | 3.00 | 0/12 |
| 5 | selective joint | 4/12 / 4/12 | 5.00 | 8/12 |
| 8 | neutral joint | 4/12 / 4/12 | 5.67 | 8/12 |
| 8 | selective joint | 4/12 / 4/12 | 5.00 | 8/12 |

B=5에서는 neutral이 같은 최종 회복을 더 적은 작성 비용과 더 작은 부작용으로 달성했다. 이 결과를 숨기면 lineage 우선 연구의 당위성을 오히려 잃는다. 다음 가설은 “언제나 lineage 우선이 낫다”가 아니라 “신뢰할 수 있는 계보가 있을 때, 그 신뢰성을 확인하는 비용까지 포함해 중립 기준보다 나을 수 있는가”로 좁혀져야 한다.

정합 힌트 6개에서는 selective의 다른 입력 성공이 4/6 대 neutral 2/6이고, 잘못된 힌트 6개에서는 0/6 대 2/6이다. 인위적으로 균형을 맞춘 구성의 전체 동률이다. 정합 집단만 골라 전체 효과라고 주장하거나, 이 비율을 실제 계보 신뢰도라고 해석하면 안 된다.

## 10. 절차 효과와 교훈의 기제 효과

선택 × 교훈의 2×2 전체 비교에서는 후보 순서, 예산 예약, 중단 여부, 실제 통합 결과가 함께 달라질 수 있다. 이것은 **전체 절차의 효과**다. 두 조건에서 final program이 다르면 그 차이를 교훈 하나의 인과 효과라고 부를 수 없다.

그래서 별도로 선택·통합을 한 번 끝내고 같은 pre-lesson bytes를 retain/suspend로 분기했다. 통합 artifact와 후기 변경은 고정하고 교훈 활성 상태만 다르게 했다. 12쌍 중 2쌍에서 다른 입력 실패가 성공으로 바뀌었고 나머지 10쌍은 동일했다. 교훈이 원래 없는 경우 효과 0인 대조도 남겼다.

이는 작성한 routing rule의 조작 검사다. 실제 모델의 기억 내용은 생성 경로와 다른 context가 함께 바뀔 수 있으므로 같은 인과 대비를 별도로 설계해야 한다. 기억을 비웠더니 좋아졌다는 관측만으로 원인 교훈을 특정했다고 단정하면 안 된다.

## 11. 그림 2와 회복 면적의 도출

![그림 2: 비용 4의 통합을 놓치는 B=5 coarse 관측](../figures/second_chance/commit-timeline.svg)

v11의 관측점은 0, B/4, B/2, 3B/4, B다. B=5라면 0, 1.25, 2.5, 3.75, 5다. 왼쪽 계단 근사는 각 구간 전체를 왼쪽에서 본 성능으로 채운다. 비용 4에서 프로그램이 성공 상태로 바뀌면 실제 [4,5) 구간은 성공이다. 그러나 3.75에서 관측한 실패값을 5까지 유지한 coarse 면적은 0이 된다.

complete commit 방식은 상태 변경 시각 c_i와 그때 효력을 갖는 상태 s_i를 사용한다. utility U가 그 상태에서의 감사 성공이면, 각 구간 길이에 U를 곱해 합한 뒤 B로 나눈다.

```text
A_coarse = Σ_j (g[j+1] - g[j]) × U(state at g[j]) / B
A_commit = Σ_i (c[i+1] - c[i]) × U(state after c[i]) / B
```

작성된 순수 결정론적 worker, 완전한 상태 로그, 고정 입력, 양의 구간을 가진 모든 상태의 새 감사가 있으면 commit 사이의 utility가 일정하다. 따라서 이 식은 관측되지 않은 성능을 임의로 보간한 것이 아니라 **그 가정 아래 실제 관측한 유한 계단 경로의 적분**이다. 이 예시에서 성공 길이 1을 B=5로 나누면 0.2다.

이 가정을 일반 LLM으로 그대로 옮기면 안 된다. 출력 샘플이 달라질 수 있으면 구간 utility를 무엇의 기대값으로 정의할지부터 정하고 상태당 반복 감사·불확실성을 추정해야 한다. 숨은 상태 변경이 있으면 partition 자체가 잘못되어 위 식이 식별되지 않는다.

## 12. 기하학 bound를 단계별로 이해하기

coarse 구간 하나를 고르자. 왼쪽 관측점 g_j부터 첫 내부 상태 변경 t_j까지는 실제 상태와 왼쪽 관측 상태가 같다. 따라서 그 구간의 오차는 0이다. t_j 이후 다음 관측점 g_(j+1)까지가 달라질 수 있는 부분이다.

utility가 0~1 범위라면 두 utility의 차이 절댓값은 최대 1이다. 그 부분의 적분 오차 절댓값은 최대 길이 `g_(j+1)-t_j`다. 모든 coarse 구간에서 이 길이를 합하고 B로 나누면 E다. 삼각부등식에 의해 `|A_commit-A_coarse| <= E`다. utility 범위가 [L,H]이면 E에 H-L을 곱한다.

B=5에서 비용 4의 변경은 다음 관측 5까지 길이 1만 노출하므로 E=0.2다. 0→1 변화가 계속 유지되면 차이 0.2로 bound를 달성한다. B=8에서는 비용 4가 이미 coarse 관측점이므로 같은 초기 통합에서 차이가 생기지 않는다. 다만 비용 5의 교훈 보류처럼 다른 사건이 관측점 4와 6 사이에 생기면 다른 panel의 차이는 생길 수 있다.

변화가 여러 번 있으면 오차가 상쇄될 수도 있다. 이 bound는 단조 증가를 가정하지 않으므로 양방향 오차를 다룬다. 완전한 로그·제한된 utility의 기하학적 결과이지 정답의 의미적 정확성, 회복 정책의 우월성 또는 외부 일반화를 보장하는 결과는 아니다.

## 13. 그림 3: coarse는 항상 보수적이지 않다

![그림 3: 초기 회복과 비영향 기능에서 반대 방향으로 나타나는 면적 차이](../figures/second_chance/area-sampling-effects.svg)

새 성공 실행은 frozen 168경로를 전부 복원하고, 292개의 새 상태 subprocess에서 876개의 panel 응답을 얻었다. 같은 상태 bytes로 비교할 수 있는 이전 응답과 모두 일치했다. 초기 utility의 면적은 16경로에서 각각 0.2 증가했고 나머지 152개는 같았다. 반대로 비영향 utility의 면적은 32경로에서 감소했고 나머지 136개는 같았다.

| 예시 절차 | 초기 coarse→commit | 다른 입력 coarse→commit | 비영향 coarse→commit |
| --- | --- | --- | --- |
| B=5 neutral joint | 0 → 1/15 | 0 → 1/30 | 1 → 1 |
| B=5 selective joint | 0 → 1/15 | 0 → 1/30 | 1 → 13/15 |
| B=8 neutral joint | 1/6 → 1/6 | 1/8 → 7/48 | 5/6 → 3/4 |
| B=8 selective joint | 1/6 → 1/6 | 1/8 → 7/48 | 2/3 → 2/3 |

입력 암기 후보를 통합하면 비영향 입력의 능력이 나빠질 수 있다. 악화가 관측점 사이에서 생기면 coarse는 왼쪽의 좋은 값을 너무 오래 유지하므로 utility를 과대평가한다. 초기 회복에서는 과소평가하고 비영향 기능에서는 과대평가할 수 있으니 “coarse면 무조건 보수적”이라는 주장은 틀리다.

그림의 y축은 12템플릿의 평균 utility 면적이다. 168독립표본의 신뢰구간은 붙이지 않는다. 정책을 다시 실행한 것도 아니므로 terminal 성공 수는 바뀌지 않았다. B=5에서 교훈 보류가 정확히 cap 5에 끝나면 terminal 다른 입력 성공은 늘어도 그 뒤 양의 비용 구간은 없다는 점도 중요하다. terminal endpoint와 area endpoint는 서로 다른 의사결정 가치를 가진다.

## 14. 결측과 실패를 어떻게 다루는가

양의 길이를 가진 상태의 새 감사가 없으면 그 구간 utility를 모른다. 모르는 구간 전체 길이를 W_unknown이라고 하자. 관측된 기여의 합 A_observed에 대해 전체 면적은 `[A_observed, A_observed + W_unknown/B]` 범위다. 점 추정은 `null`로 남긴다. 마지막 시각에만 존재하는 상태의 감사가 빠졌다면 면적 폭은 없을 수 있지만 terminal 성공을 채워 넣을 권리는 없다.

첫 v12 시도 `commit_audit_01`은 기존 area 함수에 budget 인자를 전달하지 않아 한 상태 subprocess 뒤 중단됐다. 코드·plan·failure와 디렉터리를 보존했다. 수정한 완주 실행은 새 `commit_audit_02`다. 292회는 성공 실행의 호출 수이며, 실패한 시도의 1회를 합쳐 293개의 성공 관측이라고 부르지 않는다.

실패를 보존하는 것은 결과를 비관적으로 꾸미려는 일이 아니다. 실제 어떤 호출이 시작됐고 어떤 결과가 집계에 들어갔는지 분모를 재구성할 수 있게 하는 것이다. timeout·invalid·failed integration·missing audit 역시 다음 모델 연구에서 같은 원칙으로 남겨야 한다.

## 16. 다음 실제 모델 실험의 설계

첫 확장은 실제로 모델이 만든 후보와 old evaluator가 남긴 수락·거절 이력을 수집하는 것이다. 이미 작성된 fixture를 자연 모델 이력으로 이름만 바꾸면 안 된다. 모델 ID, 설정, 파일·도구·검색 상태, 후보 bytes, 판정, 실제 교훈, 후기 변경과 비용을 먼저 고정한다. 교정은 같은 요구사항 아래 별도 승인해야 한다.

SWE-bench 같은 issue-resolution 자료는 현실적인 환경 후보지만 correction label과 rejected history를 제공한다고 가정할 수 없다. EvalPlus 같은 추가 테스트의 관점도 참고하되, 처음부터 정답 감사용으로 분리한 테스트를 통합 gate에 재사용하지 않는다. 데이터 획득·실행 전에는 선택한 subset의 라이선스, 환경 실행 가능성, 노출 이력을 따로 확인해야 한다. 이번 개정에서 새 benchmark를 다운로드하거나 모델을 호출하지 않았다.

필수 비교는 neutral early-stop, neutral joint, lineage 조건부 선택과 별도 예산의 current-only regeneration이다. 마지막 방법은 새로운 후보를 생성하므로 고정 보관함 선택과 자원 권리가 다르다. 전체 호출·입출력 토큰·평가기·도구·통합·교훈·감사 비용을 벡터로 보고해야 한다. 유용한 후보가 없는 경우, 교훈이 없는 경우, archive가 없는 경우, 교정이 논쟁 중인 경우도 flow에 남긴다.

주 평가 단위는 독립 이력 또는 correction family이고 반복 정책과 응답은 그 안에 중첩된다. 목표 효과, 멈춤 규칙, 전체 분모, 실패 처리, interval 절차를 모델 결과 전에 정한다. 정합한 계보에서의 국소 이득이 잘못된 계보에서의 손실과 신뢰성 gate 비용을 넘는지를 검증한다. 장기 재발은 복구 이후의 추가 진화 경로를 포함한 별도 후속 실험으로 유지한다.

## 17. 예상 질문과 답변

**Q. 작은 산술 fixture가 왜 필요한가?** 완전한 상태와 모든 중간 응답을 검사할 수 있어서 endpoint 혼동과 측정 오차의 반례를 정확히 만들 수 있다. 그러나 현실성을 확보하는 실험을 대체하지는 않는다. 현재 기여의 범위를 측정·비교 계약으로 한정한 이유다.

**Q. 재채점이 12/12 좋아졌으면 개선 아닌가?** 역사적 판정은 개선됐다. 그 사실만으로 현재 상태의 프로그램이나 교훈이 바뀌지는 않는다. 실제 의사결정에서 필요한 회복 endpoint가 무엇인지 별도로 보고해야 한다.

**Q. 왜 제안한 selective가 neutral에 지는 결과를 남기는가?** 그 결과가 다음 가설을 제한한다. 계보가 유용할 수 있는 조건을 지정하고 비용·부작용을 포함해 검증해야 한다. 약한 exhaustive baseline만 남기는 것보다 검토 가능한 연구가 된다.

**Q. 168경로면 통계 검정을 해도 되지 않나?** 같은 12개 작성 이력과 몇 개 입력을 반복한 경로다. 자연 이력의 모집단에서 추출한 168독립샘플이 아니다. 현재는 구성된 유한 코호트의 정확한 집계와 반례를 보고한다.

**Q. commit 사이 성공을 어떻게 알 수 있나?** 완전한 상태가 고정되어 있고 executor와 입력이 결정론적이며 해당 상태를 실제 새로 실행했다는 조건에 의존한다. 숨은 상태·외부 환경·확률성이 있으면 같은 논증을 쓸 수 없다.

**Q. bound를 통과했으니 결과가 과학적으로 인증됐나?** 아니다. 선언한 상태·utility·geometry 아래 면적 계산이 일관된다는 뜻이다. 평가기의 의미적 정답, 외부 provenance, 모델 효과나 인과적 일반화를 인증하지 않는다.

**Q. coarse가 놓친 회복만 보정하면 되지 않나?** 부작용도 관측 사이에 생긴다. 비영향 utility를 coarse가 과대평가한 32경로가 반대 방향의 반례다. 일괄적인 상향 보정은 정당하지 않다.

**Q. 292회가 840회보다 적으니 효율화 알고리즘인가?** 같은 궤적에서 byte-identical state를 중복 감사하지 않는 결정론적 실행의 결과다. 확률적 모델의 상태별 기대 utility 추정 비용이나 provider 비용의 우위는 측정하지 않았다.

**Q. 장기 recurrence를 실험했나?** 아니다. `later`는 같은 상태의 다른 입력 panel이다. 추가 진화·메모리 누적·새 선택 후의 반복 실패는 별도 실험으로 남았다.

**Q. 탑컨퍼 수준이라고 말할 수 있나?** 그 수준의 목차와 논증·비교·도표·한계 보고를 목표로 재작성했다. 심사 수락이나 제출 준비 완료를 뜻하지 않는다. 현재는 독립 실제 모델 증거와 native 비교가 필요한 개발 원고다.
