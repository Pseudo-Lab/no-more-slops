# 확인 심사 응답서 (Gemini)

- 대상: Codex 확인 심사 반영본 → 최종본(`outputs/week-03/paper.pdf`, 4쪽, 참고문헌 60편)
- 심사: `gemini.md`(Gemini 3.8 Flash), **Minor**. 2라운드 항목 전부 해소 판정. 첫 실행은 네트워크 오류(fetch failed)로 실패하여 재실행하였다.
- 독자 학습 검증: 심사위원이 원고만 읽고 가상 과제("사내 RAG 고객지원 봇 골든셋", δ=5%p)에 8단계를 적용하여 단계별 작업과 수치 통과 기준(p_d=0.15에서 468문항, 감사 304문항 0건 또는 1,000문항 5건 이하, 재현 CI [−2.5%p, 2.5%p] 등)을 작성하였다. 막힌 지점 세 곳을 아래와 같이 반영하였다.

| 지적 | 반영 |
| --- | --- |
| 막힘 1 / 권고 1: 비교 모델이 없을 때 p_d(콜드 스타트) | "비교할 모델 쌍이 없으면 최악값 p_d=0.5(약 4,360문항)를 쓴다"(본고 계산 4,358.1). Gemini가 제안한 "p_d=0.10–0.20 기본값"은 근거가 없고 과소 표본 위험이 있어 보수적 최악값으로 대체 |
| 막힘 2 / 필수 1: 연속·순위 지표의 시뮬레이션 방법 | "nDCG, 연속 점수, pass^k는 파일럿 점수를 재표집하고 라벨 오류를 주입하여 결정이 뒤바뀔 확률이 사전 한도 이하가 되는 문항 수를 정한다". 제안의 "β=0.20" 고정값은 한도를 평가 계약에서 정하도록 "사전 한도"로 둠 |
| 막힘 3 / 필수 2: 유한 모집단 보정 | "셋이 작아 감사 표본이 셋의 큰 비율을 차지하면 초기하분포(유한 모집단 보정)로 감사 수를 줄일 수 있다". 150/304/509 계산 조건의 "(유한 모집단 보정 없음)"은 이 문장과 중복되어 삭제 |
| 권고 2: 민감도 예시 "≥ 0.90" | 미반영: 근거 없는 고정값이며 비용 구조에 따라 달라지므로 평가 계약에서 정하도록 유지 |
| 부차: 대상 원고 참고문헌 수 | 심사 시점 원고는 62편, 확인 심사 반영 후 60편 |
