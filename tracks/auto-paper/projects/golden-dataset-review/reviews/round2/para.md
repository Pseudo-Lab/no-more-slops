# Round 2 — toego:paragraph-auditor 결과 (문단·절·전체 흐름)

에이전트에 쓰기 도구가 없어 반환 보고의 판정을 옮겨 적었다. 구조 판정: **minor revision**.

## 핵심 문제

1. **SimpleQA 적용 예(4.1-P4)가 표 2의 최소 판정 기준을 적용하지 않았다.** C2는 α 없이 2인 일치만, C1은 층별 문항 수 미점검, C3는 신뢰구간 상한 미계산, C6은 근거 없이 "확인 불가". 조건별 "기준 → 증거 → 판정"으로 다시 쓸 것. C3 기준의 근거(왜 탐지 차이와 비교하는지)를 본문에 설명할 것.
2. **2단 구성 논거가 4.2-P1, 5.1-P1, 5.1-P3, 6장에 반복.** 5.1-P1은 4.2 참조로 줄이고 쟁점 고유의 대립에 집중. "보조셋은 핵심셋을 최대 두 배 정도 대신" 표현이 모호.
3. **5.1의 첫째와 셋째 쟁점 경계 불명.** "출력 채점의 자동화"와 "정답 라벨 생성의 자동화"로 구분하고 OR-Bench를 셋째에 연결.
4. **결론이 네 쟁점 중 첫째 입장만 반영.** 둘째–넷째 입장, 감사의 하한성, LLM 라벨 자기 선호 미확인, 오류 탐지 성능 한계를 추가.
5. **한 문단 다주제:** 2.5-P1(Round 1 미해소), 2.6-P1, 3.3-P1, 3.5-P1, 4.1-P2, 4.2-P2.
6. **장 종합 문단(2.6-P2)이 2.6 안에 있다.** 소절 밖으로. "로그는 정답 검증을 뒤로 미룬다"의 로그 쪽 근거 없음. "만족하지 못하였고"는 종합 판단 표지 필요.
7. **측면 독립성 근거 두 건인데 "여럿".** 사례별로 통과 측면과 실패 측면을 명명. HLE 수치가 2.1과 3장 도입에 분산 → 상호 참조.
8. **4장 제목이 4.2를 덮지 못함.** "골든의 정의와 적용" 권고, 4.2 제목도 판정 모델 승인을 덮도록.

## 제안 구조

- 2장: 2.5 두 문단, 2.6 세 문단(에이전트/안전성/다국어), 장 종합은 소절 밖, 2.2에 로그 정답 출처 한 문장, 2.3은 위험 → 보완 순.
- 3장: 도입 사례에 측면 명명, 3.3 두 문단(정답 감사/시험 코드), 3.5 두 문단(오염/재현성).
- 4장 "골든의 정의와 적용": 4.1 개념의 변천, 4.2 정의와 일곱 조건(정의·대응 / 차별성 / 표 2 / C6·C7 주제문), 4.3 적용 예 SimpleQA(조건별), 4.4 2단 구성(PPI·상한 / 판정 모델 보정·승인 / 모델 선택 규모).
- 5.1: P1 축약·4.4 참조, P3 정답 라벨 생성으로 한정 + OR-Bench. 5.2 마무리 문장.
- 6장: 쟁점 2–4 입장, 감사 하한성·LLM 라벨 미확인, 종합 판단 표지, "두 사례".
