# 비슷한 스킬과의 차이

열린 PR의 `SKILL.md`를 읽고 정리했다(2026-10-18 기준, #12 paper-visuals·paper-to-latex와 #4 experiment-report-to-paper는 2026-10-19 추가). 각 스킬의 내용은 해당 PR이 바뀌면 달라질 수 있다.

| 스킬 (PR) | 입력 | 출력 | 범위 |
|---|---|---|---|
| **paper-readability-pass** (이 스킬) | 빌드된 PDF, 원고 소스, 투고처, 본문 쪽수 제한, (선택) 채택 논문 구조 분석 | 채택 논문 구조 비교 파일, 회차별 가독성 리뷰, 글·캡션만 고친 원고, 렌더링 확인 | 읽기 쉬움만 다룬다. 숫자·표 파일은 건드리지 않는다. 회차마다 새 리뷰어를 띄워 반복한다 |
| paper-review-local (#8) | 원고 패키지(LaTeX·PDF), 저장소 루트, 선택적 `sources/*.txt` | `reviews/<review-id>/` 아래 검사 보고서, 입력 해시에 묶인 지적 목록 | 섹션·인용 키·그림·PDF 가독성·ChkTeX·제공 원문과의 문장 중복을 스크립트로 검사한다. 쪽 이미지 확인도 포함하지만 글 구조·서사는 다루지 않는다 |
| paper-results-reviser (#12) | 원고(.md/.tex), 완료된 결과 폴더, (선택) 실험 계획, 형식 | `<stem>_revised.<ext>`, `revision_audit.md` | 실험 후 주장과 결과를 대조해 원고를 고친다. 가설 판정과 수치 정합이 중심이며 가독성 심사나 렌더링 확인은 없다 |
| paper-writer (#12) | 연구 계획 파일, 임시 원고, 프로젝트 식별자, 쪽수, (선택) 결과 | 결론까지 완성한 약 4쪽 원고(Markdown) | 원고 전체를 쓰거나 결과에 맞춰 다시 쓴다. 단어 수로 쪽수를 추정하며 빌드된 PDF를 보지 않는다 |
| evidence-driven-paper (#6) | 원고 소스, 결과 파일, 빌드 방법, 현재 리뷰 | 고친 원고, 주장-근거 대장, 동반 파일, 검사 하네스 결과 | 공정한 비교·기여 귀속·근거 사슬이 중심이다. 렌더링 쪽 확인을 언급하지만 채택 논문 구조 비교나 새 리뷰어 반복은 없다 |
| draft-conference-paper (#4) | 선행연구 조사 파일, 목표 학회명 | 실험 전 Abstract·Introduction·Related Work 초안(Word, LaTeX), 형식 기록 | 실험 전 앞부분 세 섹션을 새로 쓴다. 공식 양식 확인이 중심이며 완성 원고의 가독성 점검은 하지 않는다 |
| paper-visuals (#12) | 논문 파일 하나(.md/.tex), (선택) 형식·쪽수, 근거 폴더 | `<stem>_visuals.<ext>`, `<stem>_figures/`, `<stem>_visuals_audit.md` | 필요한 표·그림을 고르고 만들어 원고 사본에 넣는다. Phase G에서 생성한 그림 PNG를 하나씩 열어 글자 잘림·겹침·크기를 보고, Phase J에서 새 리뷰어 관점으로 원고 전체를 다시 읽어 그림·표·본문의 수치와 이름이 맞는지 확인한다. 점검 대상은 새로 만든 시각 자료와 그 정합성이며, 본문 글의 구조·서사는 다루지 않는다 |
| paper-to-latex (#12) | 완성 원고 하나(.md/.tex/.docx/.pdf), (선택) 시각 자료, 쪽수(기본 4) | Overleaf용 LaTeX 프로젝트, 컴파일된 PDF, ZIP, 변환·검증 보고서 | 문구·숫자를 그대로 옮기는 변환·조판 스킬이다. 컴파일 후 본문 쪽수와 참고문헌 시작 쪽을 스크립트로 검사하고 쪽 이미지를 본다. 쪽수를 맞출 때도 문장은 고치지 않는다 |
| experiment-report-to-paper (#4) | 실험 결과 Markdown 보고서, (선택) 결과 파일·기존 Word 초안, 학회·분량 | 편집 가능한 Word 논문(.docx) | 보고서에서 논문 전체를 새로 쓴다. 실험 기록용 약칭(`D`, `T03` 등)을 설명형 이름으로 바꾸는 규칙, 4쪽 요구 시 중복을 줄여 압축하는 규칙, 렌더링한 모든 쪽의 시각 검수를 포함한다. 수치·주장 범위 대조가 함께 들어 있다 |

## 겹치는 곳과 나누는 법

- 렌더링 쪽 이미지 확인은 `paper-review-local`, `evidence-driven-paper`와 겹친다. 이 스킬은 표 단 너비, 그림 상자 글자 넘침, 행 이름 줄바꿈처럼 글을 고쳐 해결하는 배치 문제만 본다. 형식 검사 전체는 `paper-review-local`에 맡긴다.
- 원고를 고친다는 점은 `paper-results-reviser`, `paper-writer`와 겹친다. 이 스킬은 숫자·결과·주장의 강도를 바꾸지 않고 문장 순서, 용어, 캡션, 소제목만 바꾼다. 결과와의 대조가 필요하면 `paper-results-reviser`를 먼저 쓴다.
- 쪽 이미지 확인은 `paper-visuals`(Phase G)와도 겹친다. `paper-visuals`는 새로 만든 그림 파일 자체를 보고, 이 스킬은 빌드된 원고 PDF 전체의 배치(표 단 너비, 그림 상자, 본문 끝 위치)를 본다. 두 스킬을 함께 쓰면 `paper-visuals`로 그림을 만든 뒤 이 스킬로 원고를 점검한다.
- 새 리뷰어 관점의 재검토는 `paper-visuals`(Phase J)에도 있다. Phase J는 같은 실행 안에서 그림·표·본문의 수치와 이름 정합성을 확인한다. 이 스킬은 회차마다 원고 PDF만 받은 별도 리뷰어를 새로 띄워 한 문장 요약 가능 여부, 걸리는 문장, 그림·표 단독 이해를 묻는다.
- 쪽수 검사는 `paper-to-latex`와 겹친다. `paper-to-latex`는 조판으로 쪽수를 맞추고 문장을 바꾸지 않는다. 이 스킬은 글을 고친 뒤 쪽수 제한을 다시 확인하는 데만 쓴다. LaTeX 변환이나 템플릿 조판이 필요하면 `paper-to-latex`를 쓴다.
- 약칭 정리와 분량 압축은 `experiment-report-to-paper`의 규칙과 겹친다. 그 스킬은 보고서에서 Word 원고를 새로 쓰는 단계에서 적용하고, 이 스킬은 이미 빌드된 원고의 용어를 한 이름으로 맞추는 단계에서 적용한다. 숫자와 결과는 바꾸지 않는다.
- 채택 논문의 구조를 기준으로 삼는 단계와, 매 회차 원고만 읽는 별도 리뷰어를 새로 띄우는 단계는 위 스킬에 없다.

요약하면 이 스킬은 글과 캡션만 고친다. 숫자와 결과 대조는 #6(evidence-driven-paper), 형식 무결성 검사는 #8(paper-review-local)에 맡긴다.
