# 형식 기록과 원고 검증

학회 규정을 확인하고 원고를 출력할 때 사용한다. 기록은 초안과 함께 `draft-notes.md`에 저장한다. 확인하지 않은 값은 미확인으로 남기고, 아래 목록을 채우기 위해 불필요한 조사나 문서를 추가하지 않는다.

## 학회 형식 기록

| 항목 | 기록할 내용 |
|---|---|
| 대상 | 공식 학회명, 연도, 트랙, 심사용 또는 최종본 모드 |
| 판단 상태 | 사용자 확정 / 입력 자료에서 확인 / 임시 가정 |
| 날짜 | 규정 확인일과 사용자 시간대, 해당 제출 회차의 상태 |
| 공식 근거 | 저자 안내, 모집 공고, 공식 템플릿의 실제 URL |
| 템플릿 | 파일명·버전·다운로드 출처, 사용한 class/style 옵션 |
| 길이 | 본문 제한, 참고문헌·부록·필수 진술 포함 여부 |
| 초록 | 문단·단어·문장 등 공식 규정과 실제 적용 |
| 인용 | 숫자형 / 저자–연도형, 참고문헌 정렬, 공식 서지 엔진·스타일 |
| 지면 | 용지·단·글꼴·배치, 공식 템플릿의 적용 여부 |
| 제출 | 언어, 제출 파일 형식, 익명성 및 필수 진술 |
| 차이 | 국문 검토용 추가 설정, Word의 근사 배치, 향후 갱신 사항 |

규정이 충돌하면 정확한 연도·트랙의 현재 공식 안내와 템플릿 정오표를 우선 확인한다. 어느 쪽이 현행인지 판단하지 못하면 양쪽 근거와 임시 선택을 남긴다. 하나의 학회에 대한 과거 기록을 다른 학회의 규칙으로 재사용하지 않는다.

예를 들어 한 공식 양식에서 저자–연도를 요구하면 본문에 `(Author et al., year)`를 쓰고, 번호를 요구하면 서지 도구가 생성한 `[n]`을 사용한다. 이 예시는 학회 규정의 대체물이 아니다. 번호·연도 접미사·정렬은 수동으로 일괄 치환하지 않는다.

## 핵심 주장과 근거 기록

원고의 논리를 지탱하는 주장에만 다음 정보를 남긴다. 모든 문장을 장황한 표로 복제할 필요는 없다.

| 원고의 핵심 주장 | 상태 | 인용키 또는 입력 위치 | 근거 위치·URL | 남은 조건 |
|---|---|---|---|---|
| 기존 방법의 메커니즘 | 원문 확인 / 요약만 확인 | 해당 키 | §·표·그림·쪽 | 읽은 범위 |
| 기존 논문의 결과 | 저자 보고값 | 해당 키 | 표·평가 설정 | 데이터·split·지표 등 |
| 실패 원인이나 연구 공백 | 근거 있는 해석 / 미검증 가설 | 관련 선행·계획서 | 지지·반대 근거 | 추가 확인 사항 |
| 제안 방법과 평가 방향 | 사용자 선택 / 잠정 제안 | 입력 파일·대화 | 선택의 근거 | 실험 전 여부 |

출처 위치를 확인하지 못했으면 만들어내지 않는다. 간접 요약을 원문 확인으로 승격하지 않는다. 서로 다른 데이터·계산량·평가 조건의 수치는 같은 순위표처럼 해석하지 않는다.

## 실험 후 보완 기록

미래 결과를 대신 쓰지 말고, 어떤 관찰이 어떤 문장을 바꿀지 적는다.

- 가설이 실제로 관찰됐는지, 반례나 효과가 없는 조건은 무엇인지.
- 주요 비교에서 얻을 지표·변동성·비용과 그 해석에 필요한 설정.
- 제안의 효과를 단순 대안과 구분할 비교 결과.
- Abstract 마지막 부분과 Introduction의 기여 표현 중 결과에 따라 수정할 부분.

이 기록은 편집 메모다. 원고에 아직 없는 실험을 수행하라는 명령이나 자동 실행 권한이 아니다.

## 완료 검증

### 내용

- Abstract, Introduction, Related Work 세 섹션과 인용 문헌 목록이 실제로 들어 있는가?
- 세 섹션에서 연구 질문, 방법의 확정 정도, 모델·데이터 명칭이 일치하는가?
- 기존 연구의 결과와 본 연구의 계획이 구분되는가? 실험 전 성능·통계적 유의성·신규성을 단정한 문장이 없는가?
- 핵심 직접 선행, 방법 중복, 알려진 한계를 공정하게 설명했는가?
- 초록이 공식 길이 규정에 맞고, 결과 자리표시자 없이 독립적으로 읽히는가?

### 인용과 서지

- 모든 본문 인용키가 서지 항목으로 연결되고, 인용하지 않은 항목은 특별한 이유 없이 출력되지 않는가?
- 두 형식의 저자·연도·접미사·번호가 동일한 논문을 가리키는가?
- 제목, 저자 순서, 연도, 발표처와 프리프린트 상태를 원문 정보와 대조했는가?
- 원문 URL/DOI가 실제 논문으로 연결되는가? 확인하지 않은 값, 내부 도구 인용 토큰, 임의의 출처 꼬리표가 없는가?
- 공식 스타일의 대소문자 처리·정렬·본문 인용 방식이 적용됐는가?

### 파일과 배치

- Word가 실제 편집 가능한 텍스트이고, 의도하지 않은 변경 제한이나 페이지 이미지로 되어 있지 않은가?
- Word 렌더링의 모든 페이지에서 글자 누락, 한글 폰트 문제, 겹침, 잘림, 고립된 제목을 확인했는가?
- LaTeX는 필요한 지원 파일과 서지를 함께 포함하며, 공식 스타일을 임의로 줄이거나 변형하지 않았는가?
- 컴파일 결과에 정의되지 않은 인용·참조, 누락 파일·글리프 또는 중대한 넘침 문제가 남아 있지 않은가? 성공 상태만 있고 경고나 화면을 확인하지 못했다면 확인 범위를 구분해 적는다.
- 가능한 경우 LaTeX PDF/미리보기도 시각 확인했는가? Word의 페이지 수를 LaTeX의 페이지 수로 보고하지 않았는가?
- 일반 LaTeX 프로젝트, 단일 파일 미리보기, ZIP, Word가 최신 본문과 동일한 인용을 담고 있는가?

검증 기록에는 수행한 검사와 결과를 적는다. 컴파일 성공, 시각 검증, 학회 규정 확인은 각각 별도의 상태다. 어느 하나로 다른 상태까지 완료했다고 쓰지 않는다.

## 자료가 부족할 때의 처리

| 상황 | 진행 방법 |
|---|---|
| MD와 BibTeX가 충분함 | 중복 조사를 줄이고 핵심 주장·서지만 대조한 뒤 작성 |
| BibTeX만 있음 | 주요 원문을 읽어 근거 확보, 방법 미정이면 잠정 질문 중심으로 작성 |
| 자료에서 연구 주제를 식별할 수 없음 | 주제 선택에 필요한 질문 하나만 하고 독립적으로 가능한 형식 확인 진행 |
| 목표 연도 미공개 | 가장 최근 공식 양식으로 초안 작성, 임시 기준임을 기록 |
| 신규성 후보가 이미 존재함 | 중복을 알리고 차이가 검증 가능한 좁은 질문으로 재구성 |
| 웹·원문 접근 불가 | 확보 자료만으로 제한하고 최신성·핵심 주장 검증의 한계 기록 |
| 렌더링·컴파일 도구 불가 | 원본과 프로젝트 보존, 실패한 단계와 미확인 상태를 구체적으로 보고 |
