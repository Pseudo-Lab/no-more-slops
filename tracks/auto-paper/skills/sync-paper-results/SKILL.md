# Sync paper results

A paper's numbers are a view of the run records. When runs finish or a setting
changes, regenerate that view, find every hand-written quote of a value that
changed, and rebuild the PDF within its page budget, without touching text the
author has frozen.

## Generated and written text

- **Generated**: result tables, figure data (pgfplots coordinates) and other
  number-dense parts sit between `% BEGIN AUTO NAME` and `% END AUTO NAME`
  (`<!-- ... -->` in Markdown). One command (for example `make final`) writes every
  block and a numbers report from the same loaded runs. Nobody edits a block by
  hand; change the generator. See [markers and the generator](references/markers.md).
- **Written**: prose, captions and the abstract. They may quote numbers; those
  quotes are checked against the blocks, not generated. A new paper can avoid
  stale quotes altogether with generated macros (`\newcommand{\AccJBFC}{74.6}`).

## The generator refuses partial evidence

Before writing anything it checks, and stops on the first failure:

- each run is complete: every example ID, the dataset digest, every method;
- each run used the declared protocol: models, prompts, limits, thresholds, the
  final-answer rule, prices;
- a value shown in two places comes from one run: a method in two tables, a
  figure's point at the default setting and the table cell;
- a derived run records its parts (paths and fingerprints).

Formatting is decided in the generator too: rounding, signed differences
(`+1.37`, `$-$0.35`), intervals in brackets, which cell is bold.

## Procedure

1. Snapshot the paper before regenerating: `cp paper/main.tex /tmp/main.before.tex`.
2. Regenerate every block with the project's command. `scripts/auto_blocks.py list
   paper/main.tex` must still list each block once.
3. Find stale quotes: `scripts/stale_numbers.py --before /tmp/main.before.tex
   --after paper/main.tex README.md`. Fix each one, or note why it stays. Then
   recheck derived claims by hand, which no script sees: differences, ratios,
   "highest", "in every run", "mostly by".
4. Respect frozen text. If the project freezes sections (in AGENTS.md or a
   decision log), do not edit them even when a new number makes a sentence false.
   List those sentences with proposed replacements and ask. Record what the
   author approved, with the date, before editing.
5. Update companion copies so they say what the paper says: README results,
   charts and images generated from a data file (the generator checks it against
   the tables), docs generated by scripts (change the script, not the file), and
   code defaults that describe the method. In the README, unless the author asks
   otherwise, keep results in a Results section that opens with the study's scope
   (models, runs, benchmark subset), state them without bold or superlatives, and
   keep numbers out of the tagline, badges and hero image.
6. Build the PDF and check it: `scripts/check_layout.py paper/main.pdf --body-pages
   4 --max-pages 6 --log paper/main.log --sections Introduction Conclusion`. Over
   budget: cut words, not layout ([page-budget playbook](references/page-budget.md)).
   Rebuild and export the PDF whenever the source changes; a PDF older than its
   source is a bug.
7. Check that the paper is in sync without writing it: run the generator on a
   copy and `diff`, or compare a block with fresh output using
   `scripts/auto_blocks.py check paper/main.tex RESULTS --from build/results.tex`.
8. Log the update in the project's validation log: date, command, run
   directories and fingerprints, blocks changed, prose edits and approvals,
   checks run with their results, page count and the PDF's SHA-256.

## Scripts

Python 3.10+, standard library. `check_layout.py` reads the PDF with poppler-utils
(`pdftotext`, `pdfinfo`, `pdffonts`), or pypdf when poppler is missing.

~~~sh
python3 scripts/auto_blocks.py list paper/main.tex           # blocks and line ranges; checks markers
python3 scripts/auto_blocks.py replace paper/main.tex RESULTS --from build/results.tex --require RESULTS RULES
python3 scripts/stale_numbers.py --before /tmp/main.before.tex --after paper/main.tex README.md
python3 scripts/check_layout.py paper/main.pdf --body-pages 4 --max-pages 6 --log paper/main.log
python3 -m unittest discover -s tests -v
~~~

`stale_numbers.py` reports values with at least three significant digits by
default (74.6, 1.37); shorter values such as 8 or 0.35 coincide too often to be
evidence (`--min-digits 1` shows them). `check_layout.py` finds headings as text
runs in `pdftotext -layout` output and reads two-column pages left column first.

## Example

In the week-2 JBFC study, `make final` derived the final runs (verifier threshold
0.5, first proposal when none passes) from recorded runs without API calls,
filled four blocks (Tables 1-3 and Figure 2's data) and wrote a numbers report;
it refuses runs whose Figure 2 point at the default limit differs from Table 2.
The Abstract, Introduction, Related Work and Method were frozen. The protocol
change made a few frozen sentences false (repair limit, example count, results),
and only those sentences were edited, after the author approved them; the
approval is recorded in AGENTS.md. The PDF keeps a four-page body with references
from page five; overflow was fixed by tightening text and captions.
