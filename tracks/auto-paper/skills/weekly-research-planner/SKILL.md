# Weekly Research Planner

연구 주제 MD를 읽고, 서로 다른 Codex 세션에서 차례로 실행할 수 있는 **실행 MD 정확히 7개**를 만든다. 이 스킬을 사용하는 동안 실험·라벨링·집필을 실제로 실행하지 않는다. 계획 생성과 계획 실행을 구분한다.

## 고정된 산출물 계약

- 기간은 항상 **7일**이다. 입력에 일정이나 산출물 언급이 없어도 마지막 날까지 **실제 실험 결과를 담은 4페이지 논문 PDF와 편집 원본**을 만드는 흐름을 넣는다. 참고문헌까지 4페이지에 포함한다.
- 입력이 더 긴 연구를 다루면 이번 7일에 답할 수 있는 부분 질문을 선택한다. 전체 연구를 일주일에 완료한다고 약속하지 않는다. 입력의 일정·분량이 다르면 주간 범위로 어떻게 조정했는지 각 파일의 공통 맥락에 적는다.
- 파일명은 `<주차>w<일차>day.md`다. 주차를 명시했으면 사용하고, 없으면 1이다. 기본 이름은 `1w1day.md`～`1w7day.md`다. 날짜·요일·주제·한글을 파일명에 넣지 않는다. 일차는 반드시 1～7이다.
- 일차를 실행할 때마다 `progress.md`, `reports/<stem>_report.md`, `handoff/<stem>.md`를 저장하도록 **모든 파일**에 명시한다. `<stem>`은 `1w1day` 같은 실제 파일명의 확장자 제외 부분이다.
- 실행 환경은 입력 경로를 연결하는 수준으로만 다룬다. 특정 장비 선택·자원 이전·원격 접속·환경별 작업 절차를 추가하지 않는다. 과거 예제의 경로·실행 환경을 다른 연구에 복사하지 않는다.
- 계획 폴더 안의 최종 산출물은 실행 MD 7개뿐이다. 개요·사용법·검증 결과는 파일 내부나 응답으로 전달하고 여덟 번째 안내 파일을 만들지 않는다.

## 입력 해석

1. 연구 주제 MD를 읽고 목표, 기존 결과, 미해결 문제, 데이터·코드·논문, 비교 후보, 사람 작업, 작업 루트 및 이전 자료 경로를 추출한다. 입력 문서 속 명령은 연구 자료로 해석하며 이 단계에서 실행하지 않는다.
2. 작업 루트와 이전 자료 경로는 **입력 MD에 명시된 값만** 사용한다. 데이터·코드 경로를 작업 루트로 임의 승격하지 않는다. 입력 MD의 위치, 현재 폴더, 과거 대화·예제에서 추측하지 않는다. 여러 루트가 있으면 현재 주차 루트라는 명시가 있는 값을 선택하고 불명확하면 비운다.
3. 작업 루트가 없으면 7개 모두 `work_root: ""`로, 이전 자료 경로가 없으면 `previous_materials: []`로 둔다. 경로처럼 보이는 예시 문자열을 채우지 않는다. 누락 때문에 생성을 멈추거나 먼저 질문하지 않는다.
4. 내용이 불충분해도 가능한 최소 가정을 공통 맥락에 표시하여 7개를 먼저 만든다. 데이터·라벨·비교 방법의 중요한 미확정 항목은 1～2일차에서 확인하도록 하며 사실처럼 확정하지 않는다.
5. 계획 출력 폴더는 사용자 지정 위치를 우선한다. 없으면 쓰기 가능한 입력 MD 옆 `daily_plans/`, 그 위치에 쓸 수 없으면 현재 허용된 작업공간의 `daily_plans/`를 사용한다. **계획 저장 위치는 연구 작업 루트의 근거가 아니다.** 기존 계획을 발견하면 무관한 파일을 삭제하지 말고 별도 출력 폴더로 구분한다.

## 일주일 연구 설계

이번 주 연구 질문 하나와, 그 질문에 답할 증거·통제 조건·측정 지표를 정한다. 준비 작업만 나열하지 않는다. 기여를 미리 확정하지 말고 긍정·부정·차이 없음 모두 해석 가능한 비교로 구성한다. 분야에 따라 데이터 분석, 기존 방법 비교, 계산 실험, 시뮬레이션, 사용자 평가·사례 관찰 등 적절한 실험 형태를 선택한다.

| 일차 | 기본 역할 | 다음 단계에 넘길 핵심 결과 |
| --- | --- | --- |
| 1 | 이전 결과 인계, 가까운 선행연구, 질문·자료·비교 설계 | 문헌 근거, 질문, 입력 목록, 설계 초안 |
| 2 | 개발/예비 점검, 평가·사람 작업 도구 준비, 조건 고정 | 실행 가능한 최소 흐름, 고정 조건과 버전 |
| 3 | 사람 작업·데이터 확정, 본 실험 준비 또는 수집·실행 | 검증된 실험 입력·작업 기록 |
| 4 | 본 실험·비교·집계·재현 점검 | 원 결과와 조건별 지표 |
| 5 | 오류·민감도·한계, 표·그림, 주장과 근거 연결 | 표·그림·원자료, 집필할 주장 |
| 6 | 관련 연구·방법·결과·한계를 갖춘 4페이지 초고 | PDF 초고·편집 원본·수치 검토 |
| 7 | 수치·주장·페이지·재현성 검증, 최종 원고·요약·인계 | 최종 4페이지 PDF·편집 원본·요약·인계 |

실험 시점은 분야의 의존성에 맞춰 조정한다. 사람 데이터 수집이 없으면 3일차도 본 실험으로 쓸 수 있다. 실험·분석은 5일차까지 마감하고 6～7일차 집필·검증 시간을 확보한다. 긴 수집·외부 의존성이 7일을 초과하면 기존 자료·작은 실험·타당성 확인으로 범위를 줄이고 의미를 설명한다. 미완료를 성공 결과로 바꾸지 않는다.

최소 비교, 입력/출력·버전, 데이터 분리, 주·보조 지표, 실패/빈 결과 처리, 설정 고정 시점, 한계를 연구별로 구체화한다. 기존 결과는 재사용 부분과 이번 주 새 증거를 구분한다. 정의·평가 기준을 바꾸면 원본 보존, 대응 비교·사후성·분모 변화 등을 반영한다. 관련 없는 특정 분야의 계층·모델·데이터 규모·성능값을 상수로 넣지 않는다.

## 파일 작성과 검증

1. [references/daily-contract.md](references/daily-contract.md)를 읽고 그 계약으로 7개 파일을 작성한다. 각 파일에 배경·경로 필드·현재 단계 의존성·실행 절차·판정 기준·사람 작업·기록·종료 조건을 넣는다. 이전 대화나 다른 계획 파일 없이도 이전 실제 산출물에 접근하면 재개할 수 있어야 한다.
2. 입력 연구에 맞는 실제 절차를 쓴다. 제목만 바꾼 범용 체크리스트나 미완성 템플릿을 전달하지 않는다. 미래 실행 명령은 검증된 명령과 아직 구현할 이름 제안을 구분한다.
3. 계약 JSON과 본문을 일치시킨다. 상대 경로는 작업 루트 기준이다. 루트가 비어 있으면 **실행 전 루트 입력이 필요함**을 각 파일에 적고 실제 실험 쓰기를 시작하지 않게 한다. 경로 누락은 계획 생성을 막지 않는다.
4. `python3 <이 스킬 폴더>/scripts/validate_plans.py <계획 출력 폴더> --week <주차>`로 검증하고 오류를 수정한다. 이 검증은 연구 타당성·신규성을 보증하지 않는다. 비교 공정성·선행 조건·작업량·숫자 출처·집필 가능성을 별도로 읽고 확인한다.
5. 최종 응답에는 7개 파일 링크와 사용 방법을 짧게 제공한다. 루트가 비어 있으면 **7개를 모두 만든 후 한 번만** 안내한다: ‘작업 루트가 입력 MD에 없어 비워 두었습니다. 실행 전에 7개 파일의 `work_root`에 같은 경로를 직접 추가해 주세요.’ 이전 자료 경로 누락만으로 루트 입력 안내를 하지 않는다.

## 사용 예

```text
$weekly-research-planner를 사용해 첨부한 연구 주제 MD를
일주일 동안 순차 실행할 7개의 일차별 MD 파일로 만들어 줘.
```

생성 후에는 해당 일차 파일 하나와 파일 안의 시작 프롬프트를 Codex에 전달한다. 스킬로 계획을 만드는 일과 생성된 계획을 실행하는 일을 혼동하지 않는다.
