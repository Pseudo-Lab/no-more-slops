# Markdown 검수 보고서 작성 형식

실제 값으로 채우며 빈 예시 행이나 미완성 문구를 남기지 않는다.

## 문서와 범위

- 입력 파일 이름/경로, 검수일, 파일 hash(가능한 경우)
- 검수 모드와 원본 미수정 여부
- 본문 인용 출현 수 / 고유 인용 수 / 참고문헌 수
- 열람 범위, 자동 추출 밖에서 확인한 영역, 확인 불가 영역
- 원문·공식 서지·저자 자료 중 사용한 근거 유형

## 총평

정상 연결 여부와 주요 보완 사항을 먼저 설명한다. 서지 실재 검증과 주장 검증, 원시 실험 검증을 구분한다.

## 필수 검수 표

| 대상 | 인용 | 연결된 논문과 방법 | 내용 검수 결과 |
|---|---|---|---|

각 행 작성 기준:

- **대상:** 절/문단/표/그림 번호와 해당 주장 요약. 여러 위치에서 다른 주장을 하면 별도 행으로 쓴다.
- **인용:** 원고에 표시된 저자–연도 또는 숫자. 서지만 있는 항목에는 “본문 인용 없음”, 근거 없는 참조 수치에는 “직접 인용 누락”이라고 쓴다.
- **연결된 논문과 방법:** 실제 논문 제목, 저자/연도/venue, 연결된 모델·방법 이름. 공식 근거로 연결되는 Markdown 링크를 포함한다.
- **내용 검수 결과:** 판정 + 서지 일치 여부 + 주장 부합 여부 + 필요한 보완. 미확인이면 무엇을 확인하지 못했는지 적는다.

논문별 확인과 인용 발생별 확인을 혼동하지 않는다. 같은 논문이 서로 다른 두 문장에 사용됐다면 두 주장 모두 다룬다. Markdown 셀의 세로 막대는 escape하여 표를 깨뜨리지 않는다.

## 수정 권고 상세

문제가 있는 항목별로 다음을 기록한다.

1. 위치와 원고 문장(필요한 부분만)
2. 판정 이유와 원문 절/표/식
3. 정확한 출처 URL 및 열람한 버전
4. 제안 수정 문장 또는 서지 정보
5. 중요도: 사실/연결 오류, 조건 명료화, 서지 완결성, 선택적 표현 개선

원문을 길게 복사하지 말고 필요한 범위에서 요약한다. 조건이 다른 결과의 예에서는 원문 조건과 사용자 조건을 각각 적고 사용자 실측 수치는 보존한다.

## 미확인 및 한계

접근 제한, 원문 부재, 중복된 판본, reference manager 필드처럼 완전히 확인하지 못한 항목을 기록한다. 초록만 확인한 경우 전체 방법·결과까지 확인한 것으로 표시하지 않는다.

## 후속 수정

검수 모드에서는 위 수정 문안을 제안했으며 Word는 변경하지 않았다고 명시한다. 수정 모드의 부가 보고서라면 실제 반영한 사항과 남은 미반영 사항을 구분한다.
