# 사전 점검표 보정

점검표는 주제를 거르는 도구다. 그런데 실제 채택 논문까지 떨어뜨린다면, 통과 후보가 0개라는 결과는 빈자리가 없다는 증거가 되지 못한다. 이 절차는 그 점을 실제 논문으로 확인하는 데 쓴다. 문헌만 보므로 비용이 거의 들지 않는다.

모의 심사 리뷰어가 본회의 가능성을 가르는지 확인하는 리뷰어 보정은 `mock-review-panel`에서 다룬다.

## 언제 쓰나

- 후보가 두 번 이상 연달아 전부 탈락했을 때.
- 점검표 문구를 바꿨을 때. 바꾼 문구는 바꾸는 데 쓰지 않은 새 표본으로 다시 확인한다.
- 목표 학회나 트랙을 바꿀 때. 예: short에서 long으로.

## 입력

| 인자 | 필수 | 설명 |
|---|---|---|
| `checklist` | 예 | 점검할 점검표. 보통 `topic-selection`의 "사전 점검표" |
| `venue` | 예 | 목표 학회와 트랙. 예: ACL short |
| `volumes` | 예 | 본회의 볼륨과 대조 볼륨의 Anthology ID. 예: `<year>.acl-short`, `<year>.findings-acl` |
| `keywords` | 예 | 제목 필터. 결과를 보기 전에 정한다 |
| `exclude` | 아니오 | 이전 보정에 쓴 논문 번호. 검증 때는 반드시 넣는다 |
| `out` | 예 | 결과 파일. 논문 폴더의 문헌 기록 아래에 둔다 |

## 절차

1. **표본 규칙을 먼저 적는다.** 결과 파일 맨 앞에 키워드, 제외 기준(대상이 텍스트 LLM이 아닌 논문 등), 순서 규칙("볼륨 순서대로 앞에서 N편")을 적는다. 그 뒤에 볼륨 BibTeX를 내려받아 규칙대로만 고른다. 고른 뒤에 바꾸지 않는다. 분야가 먼 논문이 걸려도 순서대로 넣는다.
2. **대조군을 둔다.** 본회의만 넣으면 점검표가 본회의를 떨어뜨리는지만 알 수 있다. Findings도 같은 규칙으로 같은 수만큼 넣어야 점검표가 두 그룹을 가르는지 알 수 있다.
   - Findings 볼륨이 long과 short를 나누지 않으면 쪽수로 거른다. Limitations나 References가 6쪽 이내에 시작하면 short로 본다.
   - 미채택 논문을 구할 수 있으면 함께 넣는다(OpenReview 공개 리뷰 등).
3. **보정 표본과 검증 표본을 나눈다.** 문구를 고치는 데 쓴 논문으로 고친 문구를 평가하지 않는다.
4. **판정 시점을 맞추고, 학회 표기를 가린다.**
   - 각 논문이 arXiv에 처음 올라온 날 요약서로 우리 점검표를 받았다고 가정한다. 그 날 이전의 선행만 쓴다. 첫 게시일을 확인하지 못하면 논문이 본문에서 인용한 선행만 쓰고, 그 사실을 한계에 적는다.
   - 가능하면 학회 표기(머리글, 쪽 아래의 Proceedings 문구)를 가린 텍스트로 판정한다.
5. **항목별로 판정한다.**
   - 기반 논문에 대한 항목(채택, 시기, 저자, 인용)은 그 논문이 직접 확장한 기반 논문으로 판정한다. 논문 자신이나 그 저자로 판정하지 않는다.
   - 탈락 관문은 통과/불통과로, 위험 항목은 낮음/중간/높음으로 적는다.
   - 판정마다 근거 선행과 원문 쪽을 적는다.
   - 논문이 실제로 무엇으로 붙었는지 기여 유형으로 적는다.
6. **집계하고 판단 규칙을 적용한다(아래).**
7. **수정안을 낸다.** 점검표 파일은 직접 고치지 않는다. 결과 파일에 "지금 문구 / 수정안" 표로 제안하고, 사람이 승인하면 고친다. 고친 뒤에는 바뀐 날짜와 결과 파일 위치를 점검표 옆에 한 줄 남긴다.

## 판정 표 양식

논문마다 한 줄씩 적는다.

| 번호 | 논문 (쪽) | 기반 논문 | 이미 채워짐 | 실패가 나는가 | 관문 | 새로움 위험 | 본회의 근거 위험 (유형) |
|---|---|---|---|---|---|---|---|

집계는 그룹마다 한 열로 둔다.

| 지표 | 본회의 | Findings | 미채택 |
|---|---|---|---|
| 관문 통과 편수 | | | |
| 항목별 탈락 편수 | | | |
| 위험 항목 등급 분포 | | | |
| 기여 유형 분포 | | | |

## 판단 규칙

- **과하다:** 탈락 관문 하나가 본회의 표본의 절반 이상을 떨어뜨리면 그 항목은 과하다.
- **잘못 적용됐다:** 관문이 채택 논문을 떨어뜨린 경우마다 원인을 적는다. 문구가 과한지, 적용 대상이 틀렸는지(예: 기반 논문이 아니라 논문 자신을 봄), 분야가 맞지 않는지(예: 행동 연구용 항목을 방법론 논문에 적용함) 가린다.
- **변별력이 없다:** 본회의와 Findings의 통과율이나 위험 분포가 같으면 그 항목은 본회의 가능성을 가르지 못한다. 그런 항목은 거르는 용도로만 쓴다.
- **맞게 작동했다:** 관문이 채택 논문을 떨어뜨렸어도, 우리가 같은 처지라면 접는 것이 맞는 경우가 있다. 예: 동시 연구와 기능상 같은 경우. 이런 경우는 수정하지 않는다.
- **너무 느슨한지:** 미채택 표본 없이는 판단하지 않는다. "알 수 없음"으로 적는다.

## 기록 위치

- 점검표 보정과 검증 결과는 논문 폴더의 문헌 기록에 둔다.
- 승인된 수정은 `topic-selection`에 반영하고, 날짜와 결과 파일 위치를 남긴다. 주제 목록 문서의 "주제 고를 때 지킬 것"에 한 줄로 요약한다.

## 한계 (결과 파일에 반드시 적는다)

- **표본 수:** 그룹당 몇 편이면 비율 하나의 불확실성이 크다.
- **판정자 수:** 판정자가 1명이면 일치도를 잴 수 없다. 가능하면 두 번째 판정자(다른 세션)가 같은 표본을 따로 판정한다.
- **사후 판정 편향:** 학회와 결과를 알고 판정하면 위험 등급이 그쪽으로 기운다.
- **시점:** 첫 게시일을 모르면 동시 연구를 놓친다.
