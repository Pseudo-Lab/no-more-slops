# launch-basics

핵심 기능보다 먼저 한다. 이게 있어야 다음 날부터 매 기능을 "진짜 사용자에게 보내도 되는 상태"에서 확인한다.

## 입력
- 헌법(데이터·동의 원칙), 운영 URL, 서비스명(사람 결정), 개인정보 담당 표기 방식(사람 결정), 분석 속성 id(사람이 만든다).

## 절차
1. **랜딩** — 문제 한 문장 + 약속 한 문장 + 로그인 버튼. OG 이미지 1장.
2. **약관·처리방침** — 적용 법령을 WebFetch로 확인하고 초안. 국외 이전·민감정보가 있으면 동의 항목을 **각각 따로**. 처리방침에는 "무엇을 저장하지 않는지"를 명시.
3. **탈퇴** — security definer RPC 하나로 사용자와 그가 만든 데이터 전부 삭제. 되돌릴 수 없는 동작이므로 확인 모달.
4. **에러·빈 화면** — error.tsx, not-found, 빈 목록 문구.
5. **분석 퍼널** — 단계마다 이벤트 1개(랜딩 → 로그인 → 핵심 행동 → 저장 → 확산). `track()` 헬퍼 하나. 보내는 건 단계 이름뿐: 이름·수치·id 금지, 개인 식별 URL은 마스킹. 헤드리스 Chrome으로 collect 요청이 실제로 나가는지 검증.
6. **도메인** — 등록은 사람, DNS 레코드 값은 Claude가 만들고 `vercel api`로 TXT 검증.
7. 각 항목은 `ship-loop`로 PR 하나씩.

## 멈추는 지점 (사람 몫)
- 서비스명, 개인정보 담당 표기, 도메인 등록·DNS 입력, 분석 속성 생성.

## 산출물
남에게 보낼 수 있는 링크, 퍼널 이벤트 정의표(단계 ↔ 이벤트명). 다음 단계는 `core-feature-with-review`.
