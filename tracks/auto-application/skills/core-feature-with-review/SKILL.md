# core-feature-with-review

AI 결과가 확인 없이 저장되는 길을 만들지 않는다. 틀릴 수 있는 것은 사람이 한 번 보고 들어간다.

## 입력
- 약속 한 문장과 첫 화면 3개(`constitution-first` 입력), 헌법, 운영 URL.
- 사람이 제공: AI API 키(호스팅 Sensitive 환경변수에만), 시험용 실제 입력 1~2개(scratchpad에만, 레포·노트 금지).
- 읽기 규칙은 사람이 정한다(예: 인쇄된 것만, 판정은 체크된 칸에서만).

## 절차
1. **spec** — `ship-loop` 3단계. spec-kit이 있으면 `specify → plan → tasks → implement`.
2. **클라이언트 준비** — 큰 입력은 브라우저에서 줄인다(글자 추출, 이미지 축소, 민감 문자열 가림). 서버 요청 한계(Vercel 4.5MB)를 상수로 두고 why-주석.
3. **서버 액션 하나** — 순서 고정: 로그인 → 필요한 동의 확인 → 남용 상한(크레딧·일일 제한) 차감 → 외부 호출 → 후처리. 키는 서버에서만 읽는다.
4. **외부 AI 호출** — `json_schema` strict, `store:false`, 추론 없음(단순 전사일 때). 프롬프트는 요청마다 동일하게 유지(캐시). 모델이 지어내는 지점을 규칙 문장으로 막는다.
5. **확인 화면** — 결과를 편집 가능한 폼으로. 사용자가 고치고 지우고 저장. 저장 액션은 길이·형식 검증, 부분 실패면 롤백.
6. **샘플 폴백** — 키가 없는 환경(미리보기·로컬)에서는 예시 값 + 경고 문구로 흐름을 볼 수 있게.
7. **검증** — 헤드리스 Chrome E2E(업로드 → 확인 → 저장), 운영 URL 확인. `ship-loop` 6~7단계.

## 멈추는 지점 (사람 몫)
- API 키 발급·등록, 시험용 데이터 제공과 폐기, 읽기 규칙·남용 상한 수치.

## 산출물
동작하는 핵심 기능 PR, 프롬프트·스키마 파일(실측 스킬이 재사용). 다음 단계는 `model-bakeoff`.
