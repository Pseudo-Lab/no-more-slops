# model-bakeoff

실측 없이 모델을 고르지 않는다. 표 한 장이 "왜 이 모델인가"의 근거가 되고 PR 본문과 발표에 그대로 들어간다.

## 입력
- 핵심 기능의 프롬프트와 출력 스키마(`core-feature-with-review` 산출물).
- 시험용 입력 1~3개(사람 제공, scratchpad에만)와 정답 기준(예: 17개 항목의 값·판정).
- 사람이 정한 후보 모델과 방향(싸게? 정확하게? 구독으로?).

## 절차
1. **스크립트 틀** — 입력·스키마는 파일로 공유하고 경로만 다르게: `openai.mjs`(직접 API), Agent SDK(`persistSession:false, tools:[]`), `codex exec --ephemeral --output-schema -i`. 출력은 `<경로>-<모델>-<effort>.json`.
2. **같은 조건** — 같은 입력, 같은 스키마, reasoning effort 명시, 3회 반복(편차 확인).
3. **채점** — 정답 기준과 자동 비교(값·판정 일치 수). 사람이 눈으로 보는 건 불일치 항목만.
4. **표** — 모델 · 수치 · 판정 · 토큰 · 건당 비용(원) · 시간 · 경로. 비용은 공개 단가로 계산하고 날짜를 적는다.
5. **결정** — 다 맞추는 것 중 가장 싼 것. 남용 상한은 비용 × 예상 호출로 역산(가입 크레딧 N회, 월 한도).
6. **기록** — 결정 근거를 코드의 `MODEL` 상수 옆 Business 주석과 README 표에 남긴다. 스냅샷 없는 모델이면 Future 주석.

## 가드레일
- 시험용 개인 데이터와 출력은 scratchpad에만. 레포·노트·아티팩트 금지.
- 에이전트 실행은 세션을 남기지 않게(`--ephemeral`, `persistSession:false`). SDK에 그 옵션이 없으면 실행 뒤 세션 파일을 지운다.

## 멈추는 지점 (사람 몫)
- 후보 모델·방향, 남용 상한 수치, 유료 호출 승인.

## 산출물
비교 표(README·PR용), 운영 모델 결정, 남용 상한. 다음 단계는 `glance-and-guardrails`.
