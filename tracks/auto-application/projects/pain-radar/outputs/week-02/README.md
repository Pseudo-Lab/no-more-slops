## 한계점

제출 시점(2026-10-19) 기준입니다. 검색 품질 개선은 서비스 저장소 PR #48(키워드 선택, GitHub best match, HN 부분 일치)로 올렸고, 아래는 그 뒤에도 남는 한계입니다.

**검색이 찾는 범위**

- 출처가 셋뿐입니다. GitHub·Hacker News·OpenAlex 밖에 있는 앱스토어 앱, Product Hunt, Reddit, 국내 커뮤니티, 특허, 이미 문 닫은 서비스는 보이지 않습니다. "아무것도 안 나옴"이 "아무도 안 만듦"을 뜻하지 않습니다.
- 키워드 일치 검색입니다. 같은 문제를 다른 단어로 쓴 결과(trial ↔ subscription)는 놓치고, 같은 단어를 다른 뜻으로 쓴 결과(cancel ↔ "Cancel Culture" 논문)는 섞입니다. 키워드는 불용어를 빼고 영어는 문장 끝, 한글은 문장 앞 단어를 고르는 규칙이라 문장 구조가 다르면 핵심어를 놓칩니다.
- 한글은 번역 없이 반만 됩니다. Hacker News는 영어 자료라 한글로는 거의 0건이고, GitHub도 한국어로 설명을 쓴 저장소만 걸립니다. 조사는 명사 끝과 헷갈리지 않는 것(을/를/은/는/에서/으로/에게)만 떼고, 동사 활용("해지하는")은 그대로 남습니다.
- 순위는 각 API의 순위를 그대로 씁니다. 출처끼리 관련도를 비교하거나 중복(같은 제목의 HN 글 두 개)을 합치지 않습니다.
- 출처마다 기본 8개, 최대 25개이고 다음 페이지가 없습니다.
- 품질 평가는 작성자 한 명이 영어 질문 5개를 판정한 것뿐입니다. 정답 세트나 사용자 판정이 없습니다.

**결과를 읽는 법**

- 별점·인용 수·HN 점수는 관련도나 품질이 아닙니다. 마지막 업데이트, 유지 여부, 실제 사용자 수는 보여 주지 않습니다.
- 헌법상 "만들어라/말아라", 경쟁 강도 같은 결론을 내지 않습니다. 결과가 많다고 시장이 포화됐다는 뜻도, 적다고 기회라는 뜻도 아닙니다. 판단은 사람 몫입니다.

**운영**

- 운영에 `GITHUB_TOKEN`이 없습니다. GitHub 비로그인 검색 한도(서버 IP당 분당 10회)를 모든 사용자가 나눠 써서, 몇 명만 동시에 써도 GitHub 결과가 오류로 빠집니다. 다른 출처 결과와 오류 표시는 그대로 나옵니다.
- 세 외부 API에 기대고, 한 출처가 10초 안에 답하지 않으면 그 출처는 오류로 표시합니다.
- 일일 한도(사용자당 검색 100회, 키당 MCP 100회)는 임시값입니다.
- 로그인은 카카오 하나뿐이고, 제출 시점에 운영 카카오 로그인 설정이 끝나지 않았습니다.
- 운영 `NEXT_PUBLIC_GA_ID`가 비어 있어 퍼널 지표가 아직 쌓이지 않습니다.
- Vercel과 GitHub가 연결되지 않아 배포를 손으로 합니다.
- MCP는 운영에서 키 없는 호출이 401인 것까지만 확인했고, 실제 에이전트가 운영 키로 붙어 본 적은 없습니다.

**개인정보**

- Pain Radar는 입력 문장을 저장하지 않지만, 검색하려면 그 문장(키워드)을 GitHub·Algolia·OpenAlex(모두 미국)로 보냅니다. 그쪽의 로그 보관은 통제하지 못합니다. 처리방침에 국외 이전 대상으로 적었지만, 민감한 사업 아이디어는 입력하지 않는 편이 안전합니다.
- 검색 기록을 저장하지 않으니 지난 결과를 다시 보거나 팀과 공유할 수 없습니다. 의도한 제약입니다.

## 레슨런

- **한글은 AI 없이 반만 된다.** 검색어에 한글을 남기니 GitHub는 한국 저장소가 나오지만 Hacker News는 0건입니다. 번역 AI를 넣으면 헌법상 "번역·키워드 추출까지만"이라는 경계와 비용 상한을 같이 정해야 해서 이번 주에는 넣지 않았습니다.
- **별점 정렬은 관련 없는 인기 저장소를 끌어온다.** GitHub를 `sort=stars`로 받으니 검색어와 관계가 약한 대형 저장소가 위에 옵니다(결과 스크린샷 참고). best match와 키워드 선택을 바꾸니 영어 질문 5개의 상위 3개 관련도가 0/15에서 14/15가 됐습니다(PR #48).
- **로컬 Supabase가 여러 개면 포트를 이름처럼 다뤄야 한다.** 다른 프로젝트(543xx)와 분리해 544xx를 썼는데, 검증 중 한 번 다른 프로젝트 포트로 요청해 엉뚱한 DB에 테스트 계정을 만들었습니다. env-split 스킬에 "요청 전 포트와 프로젝트 이름 확인"을 넣을 계획입니다.
- **디자인 검증은 로그인 뒤 화면까지 가야 의미가 있다.** 로컬 테스트 계정으로 세션을 만들어 검색 결과·설정·탈퇴 확인창까지 찍은 뒤에야 터치 영역 12곳, 폰 헤더 넘침, 위험 버튼 대비 문제가 보였습니다.
- **GitHub 연결 없는 수동 배포는 PR 머지와 배포가 따로 논다.** Vercel에 GitHub 로그인 연결이 없어 `vercel deploy --prod`를 손으로 돌렸고, CLI 첫 시도가 "Not authorized"로 실패하는 일이 반복됐습니다.
