# Pawstamp 만들면서 배운 것

AI(Claude)와 같이 MVP를 만들면서 2026-10-09 하루 동안 정리한 레슨런.

## 1. 웹앱은 "화면"과 "데이터"를 맡는 서비스가 따로 있다

- **몰랐던 것**: 사이트를 띄워주는 서비스(Vercel, Netlify)만 있으면 될 줄 알았다. 그런데 사람들이 올린 사진·강아지 정보·하트를 저장하는 서비스(Supabase)가 따로 필요했다.
- **결과**: 처음 버전은 데이터가 각자 브라우저에만 저장돼서, 내가 올린 사진을 친구가 볼 수 없는 상태였다.
- **다음엔**: 기획 단계에서 "누가 쓴 데이터를 누가 보나?"부터 정한다. 다른 사람이 봐야 하면 DB 서비스가 필요하다.
  - 화면 호스팅: Vercel / Netlify
  - 데이터·사진 저장: Supabase / Firebase
  - 로그인: 보통 DB 서비스에 같이 들어 있음 (MVP에서는 빼고 브라우저별 ID로 대신함)

## 2. 조건 없이 맡기면 "연동하기 쉬운 것"을 고른다

- **있었던 일**: 지도 API를 그냥 맡겼더니 키 발급 없이 바로 붙는 OpenStreetMap이 골라졌다. 붙이기는 쉬웠지만 한국 정보가 오래되고 디자인도 복잡했다. 처음 고른 CARTO 지도는 그사이 정책이 바뀌어 API 키가 필요해서 아예 안 나왔다.
- **배운 것**: AI는 기준이 없으면 "바로 돌아가는 것"을 우선한다. 품질 기준은 내가 줘야 한다.
- **다음엔**: 외부 서비스를 고를 때 기준을 같이 준다.
  - 예: "한국 사용자용이라 국내 지도 정확도가 제일 중요해. 키 발급은 내가 할게. 후보 2~3개 비교해서 추천해줘."
  - 무료 한도, 가입·결제 카드 필요 여부, 데이터 정확도, 디자인 자유도를 비교표로 받는다.

## 3. "MVP"라고만 하면 만들기(Create)만 나온다

- **있었던 일**: 사진 올리기, 하트, 구경하기만 요청했더니 정말 그것만 만들어졌다. 내 강아지 정보 **수정**, 사진 **삭제**, 잘못 올린 장소 **정리** 같은 관리 기능은 아예 없었다. 강아지를 등록하고 나서야 고칠 수 없다는 걸 알았다.
- **배운 것**: 기능 목록을 줄 때 데이터마다 CRUD(만들기·보기·수정·삭제)를 다 따져봐야 한다. "올린다"가 있으면 "고친다·지운다"도 거의 항상 필요하다.
- **다음엔**: 기능을 요청할 때 데이터별로 체크한다.

  | 데이터 | 만들기 | 보기 | 수정 | 삭제 |
  |---|---|---|---|---|
  | 강아지 프로필 | ✅ | ✅ | ✅ (나중에 추가) | ❌ 아직 없음 |
  | 사진(발도장) | ✅ | ✅ | ❌ 아직 없음 | ❌ 아직 없음 |
  | 장소 | ✅ | ✅ | ❌ | ❌ |
  | 하트 | ✅ | ✅ | 취소 가능 | — |

## 4. 그 밖에 알게 된 것

- **"나만 수정 가능"은 로그인이 있어야 제대로 된다.** 지금은 브라우저마다 ID를 만들어서 구분하는데, 브라우저를 바꾸거나 기록을 지우면 내 강아지를 못 고친다. 실제 서비스면 카카오 로그인 같은 걸 붙여야 한다.
- **배포 권한은 미리 확인해야 한다.** Claude에 연결된 Vercel 권한으로는 새 프로젝트를 만들 수 없어서, 마지막 배포는 결국 내가 터미널에서 직접 해야 했다.
- **폰 사진의 위치 정보는 생각보다 잘 빠진다.** 카톡·인스타로 받은 사진이나 아이폰에서 웹으로 올린 사진은 위치 정보가 지워질 수 있다. 그래서 "지도에서 직접 고르기"를 같이 만들어야 했다.
- **요구사항은 만들면서 계속 생긴다.** 이름(킁킁지도 → 발도장 → Pawstamp), 견종 캐릭터, 축소했을 때 견종별 묶음, 첫 인사, "1마리" 대신 "친구 1명" 같은 말투는 화면을 보고 나서야 떠올랐다. 처음부터 완벽하게 정하기보다 빨리 띄워보고 고치는 게 맞았다.
- **글씨체와 로고가 첫인상을 다 정한다.** 기능이 같아도 동글동글한 글씨체(주아체)와 발바닥 아이콘은 유치해 보였다. Pretendard와 도장 모양 로고로 바꾸니 서비스처럼 보이기 시작했다.

## 5. 남의 서비스를 가져다 쓰는 것도 처음이었다

- **처음 알게 된 것**: 지도, 데이터 저장, 배포를 다 직접 만드는 게 아니라 이미 있는 서비스를 "빌려서" 붙인다. 이번에 붙인 것만 해도 이렇다.

  | 맡긴 일 | 가져다 쓴 서비스 | 내가 직접 해야 했던 것 |
  |---|---|---|
  | 데이터·사진 저장 | Supabase | 가입, 프로젝트 만들기 |
  | 사이트 띄우기 | Vercel | 로그인 승인 (터미널에 뜬 코드 확인) |
  | 지도 | OpenStreetMap → 카카오맵 | 카카오 개발자 가입, 앱 만들기, 키 발급, 사이트 주소 등록 |
  | 글씨체 | Pretendard (무료 공개 폰트) | 없음 |

- **배운 것**
  - 서비스마다 **가입과 키 발급은 내가 직접** 해야 한다. 로그인·비밀번호·결제처럼 계정에 관한 일은 AI가 대신 못 한다.
  - **키에도 종류가 있다.** 브라우저에 공개돼도 되는 키(Supabase 공개 키, 카카오 JavaScript 키)와 절대 공개하면 안 되는 비밀 키가 따로 있다. 공개 키는 "등록한 사이트 주소에서만 쓸 수 있게" 막아두는 식으로 보호한다.
  - **남의 서비스는 내 마음대로 안 바뀐다.** 처음 쓰려던 CARTO 지도는 그사이 정책이 바뀌어서 갑자기 키를 요구했다. 무료 한도, 요금, 정책이 바뀔 수 있다는 걸 전제로 골라야 한다.
  - **사이트 주소가 바뀌면 서비스 설정도 같이 바꿔야 한다.** 카카오맵은 등록된 주소에서만 뜨기 때문에, 로컬 테스트 주소와 배포 주소를 둘 다 등록해야 했다.

## 6. PM으로 일한 경험이 실제로 쓰인 순간: 데이터가 쌓여야 나갈 수 있는 기능을 구분했다

- **있었던 일**: 서비스를 띄우고 나니 아이디어가 한꺼번에 나왔다. 구 단위로 어떤 견종이 제일 많이 다니는지, 오늘 가장 많이 등록된 장소, 길고양이 캐릭터.
- **정리한 방식**: 다 만들고 싶었지만, 실무에서 하던 대로 "지금 바로 가치가 생기는 기능"과 "데이터가 쌓여야 의미가 생기는 기능"으로 나눴다.

  | 기능 | 데이터 없이도 가치가 있나? | 판단 |
  |---|---|---|
  | 길고양이 캐릭터 | 있다. 오늘 올린 한 장부터 바로 쓰인다 | **지금 만든다** |
  | 구별 인기 견종 | 없다. 사진이 몇 장뿐이면 "1위: 보스턴테리어 3장"이 된다 | 데이터가 쌓인 뒤 |
  | 오늘 가장 많이 등록된 장소 | 없다. 하루에 몇 장 안 올라오면 순위가 의미 없다 | 데이터가 쌓인 뒤 |

- **배운 것**: 통계·랭킹 기능은 사용자가 모여야 빛난다. 초반에는 오히려 "텅 빈 랭킹"이 서비스가 비어 보이게 만든다. 그래서 먼저 사람이 올리고 싶게 만드는 기능(캐릭터, 올리기 경험)에 집중하고, 랭킹은 "몇 장 이상 쌓이면 연다"는 기준을 정해두는 게 맞다.
- **재밌었던 점**: 혼자 만드는 사이드 프로젝트인데도, 회사에서 우선순위를 정하던 기준이 그대로 통했다. AI가 만드는 속도가 빨라질수록 "뭘 먼저 만들지" 정하는 일이 더 중요해진다는 걸 느꼈다.

## 7. 남이 쓰기 시작하면 바로 "나쁜 사용"부터 들어온다

- **있었던 일**: 링크를 동생에게 보냈더니 테스트하자마자 욕설을 적어보고, 사람 얼굴 사진을 올려보려고 했다. 나 혼자 쓸 때는 한 번도 생각 못 한 경우다.
- **한 것**:
  - **욕설 막기**: 띄어쓰기나 숫자를 끼워 넣는 우회("시 1 발")까지 잡도록 글자만 남겨서 검사했다. "강아지 새끼", "시바견"처럼 이 서비스에서 자연스러운 말은 일부러 막지 않았다. 브라우저에서 먼저 안내하고, 우회해서 보내도 **DB에서 한 번 더 막는다.**
  - **사람 얼굴 막기**: 사진을 고르면 브라우저에서 얼굴 감지(구글 MediaPipe)를 돌려서, 사람 얼굴이 보이면 올리지 못하게 했다. 실제 강아지 사진 6장으로 오탐이 없는 것도 확인했다.
- **배운 것**
  - 사람들이 직접 올리는 서비스(UGC)는 **"나쁜 사용을 어떻게 막을까"가 기본 기능**이다. 수정·삭제처럼, 처음 기획에 안 넣으면 아무도 안 만들어준다.
  - 금지어는 서비스 맥락에 맞춰야 한다. 일반 욕설 목록을 그대로 쓰면 "새끼", "시바" 같은 말 때문에 강아지 서비스가 고장 난다.
  - 브라우저에서만 막으면 우회할 수 있다. **중요한 규칙은 서버(DB)에서도** 막아야 한다. 얼굴 감지는 아직 브라우저에서만 하고 있어서, 나중에는 신고 버튼과 관리자 삭제가 필요하다.
  - **집 위치도 새어 나간다.** 동생이 장난으로 아파트 이름을 장소 이름으로 핀을 찍었다. 장소 검색에 아파트가 그대로 나오니, 마음만 먹으면 누구나 자기 집(이나 남의 집)을 공개할 수 있다. 일단 근처 한강 산책길로 옮겼고, 다음엔 아파트·주거지를 고르면 경고하고 위치를 흐리게 하는 장치가 필요하다.
  - 길고양이 위치를 100m 흐리게 한 것도 같은 맥락이다. **기능을 만들 때 "이걸 나쁘게 쓰면?"을 같이 묻는다.**

## 다음에 AI한테 처음 맡길 때 쓸 체크리스트

1. 누가 쓰고 누가 보나? (나만 / 친구들 / 모두) → DB·로그인 필요 여부
2. 데이터별 만들기·보기·수정·삭제 중 뭐가 필요한가?
3. 외부 서비스(지도, 로그인, 결제)의 선택 기준: 정확도, 디자인, 무료 한도, 가입 절차
4. 톤앤매너: 서비스 이름, 말투(사람한테 하듯), 글씨체, 레퍼런스 앱
5. 배포 방법과 권한: 누가, 어디에, 어떤 계정으로
6. 기능마다 "데이터가 쌓여야 의미가 생기나?" 체크 → 지금 만들 것과 나중에 열 것 나누기
7. "이걸 나쁘게 쓰면?" 체크: 욕설, 얼굴·개인정보, 위치 노출, 신고·삭제 방법
